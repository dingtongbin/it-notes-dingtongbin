﻿﻿# 并发：多线程与多进程

并发解决"等待时间"的浪费：网络请求、文件读写、批量任务。这一篇讲threading和multiprocessing的用法、线程安全的本质，以及"什么场景选哪个"的判断标准。

## 三个概念先分清

- **并发（concurrency）**：交替处理多个任务（单核也能并发）。
- **并行（parallelism）**：同一时刻真的在多个核上跑。
- **异步（asyncio，下一篇）**：单线程内切换任务，适合IO等待。

你写的是并发代码，能不能并行取决于解释器有没有真的多核在跑。选择模型的关键问题是：你的任务**卡在等待上**（IO密集：网络、磁盘）还是**卡在计算上**（CPU密集：加密、图像处理）？

## threading：多线程

### 基本用法

```python
import threading
import time

def worker(name: str, seconds: float):
    print(f"{name} 开始")
    time.sleep(seconds)                 # 模拟IO等待
    print(f"{name} 结束")

t1 = threading.Thread(target=worker, args=("任务A", 1.0))
t2 = threading.Thread(target=worker, args=("任务B", 2.0))

t1.start()      # 启动线程
t2.start()
t1.join()       # 等待线程结束
t2.join()
print("全部完成")
```

start() 之后代码继续往下跑（主线程不等）；join() 阻塞等待指定线程结束。args是元组，按位传给target函数。

### 并发下载的提速验证

```python
import threading
import time
import urllib.request

urls = [f"https://httpbin.org/delay/1" for _ in range(5)]

def fetch(url):
    with urllib.request.urlopen(url, timeout=10) as resp:
        return len(resp.read())

# 串行
start = time.perf_counter()
results = [fetch(u) for u in urls]
print(f"串行: {time.perf_counter() - start:.1f}s")     # 约5秒+

# 多线程
start = time.perf_counter()
threads = [threading.Thread(target=fetch, args=(u,)) for u in urls]
for t in threads:
    t.start()
for t in threads:
    t.join()
print(f"并发: {time.perf_counter() - start:.1f}s")     # 约1秒，因为等待被重叠了
```

线程在"等待网络响应"期间让出GIL（见下文），其他线程接着请求——IO密集任务多线程有效的原理。

### ThreadPoolExecutor：生产级写法

手动管线程太啰嗦，标准库线程池一步到位：

```python
from concurrent.futures import ThreadPoolExecutor, as_completed
import urllib.request

urls = ["https://httpbin.org/delay/1"] * 5

def fetch(url):
    with urllib.request.urlopen(url, timeout=10) as resp:
        return url, len(resp.read())

with ThreadPoolExecutor(max_workers=10) as pool:
    # map：按提交顺序返回结果
    for url, size in pool.map(fetch, urls):
        print(url, size)

    # as_completed：谁先完成先处理谁（更常用）
    futures = {pool.submit(fetch, u): u for u in urls}
    for future in as_completed(futures):
        try:
            url, size = future.result()     # 重新抛出任务里的异常
            except Exception as e:
            print(f"{futures[future]} 失败: {e}")
        else:
            print(f"{url} 完成，{size} 字节")
```

submit返回Future对象（"未来的结果"），result() 阻塞取值并把任务内异常原样抛出——错误处理不会被并发打乱。

### 线程安全与锁

多个线程同时读写共享数据会互相踩踏：

```python
import threading

counter = 0

def increment():
    global counter
    for _ in range(100_000):
        counter += 1          # 不是原子操作！读 -> 加1 -> 写回，三步之间可能被切走
        threads = [threading.Thread(target=increment) for _ in range(4)]
for t in threads:
    t.start()
for t in threads:
    t.join()
print(counter)    # 理论400000，实际每次运行都小于它
```

counter += 1在字节码层面是三条指令，线程切换可以发生在任意两条之间，两次读到同一个旧值就会丢更新。

用锁保护临界区：

```python
import threading

counter = 0
lock = threading.Lock()

def increment():
    global counter
    for _ in range(100_000):
        with lock:            # 同一时刻只有一个线程能进入
            counter += 1

threads = [threading.Thread(target=increment) for _ in range(4)]
for t in threads: t.start()
for t in threads: t.join()
print(counter)    # 400000，稳了
```

用锁的纪律：**锁的粒度尽量小**（只包住共享数据的读写，别把整个函数锁进去）；**所有线程用同一把锁**；避免嵌套加锁（死锁之源）。

更简单的替代：queue.Queue天生线程安全，生产者-消费者模型用它，根本不用自己碰锁：

```python
import queue
import threading

q: queue.Queue[int] = queue.Queue()

def producer():
    for i in range(10):
        q.put(i)
    q.put(None)               # 结束哨兵
    def consumer():
    while True:
        item = q.get()
        if item is None:
            break
        print("处理", item)
        q.task_done()

threading.Thread(target=producer).start()
threading.Thread(target=consumer).start()
```

原则：**能用Queue传数据就别共享变量**，共享变量才需要锁。

## multiprocessing：

多进程CPU密集任务（循环计算、压缩、图像处理）用多进程——每个进程独立解释器、独立GIL，真正吃满多核。

```python
import multiprocessing

def cpu_task(n: int) -> int:
    total = 0
    for i in range(n):
        total += i * i
    return total

if __name__ == "__main__":        # Windows/macOS必须有这个守卫！
    n = 10_000_000
    # 串行import time
    start = time.perf_counter()
    results = [cpu_task(n) for _ in range(4)]
    print(f"串行: {time.perf_counter() - start:.1f}s")

    # 多进程start = time.perf_counter()
    with multiprocessing.Pool(processes=4) as pool:
        results = pool.map(cpu_task, [n] * 4)
    print(f"并行: {time.perf_counter() - start:.1f}s")   # 约为串行1/4（4核时）
```

两个关键点：

1. **Windows下必须if __name__ == "__main__": 守卫**：子进程通过import主模块的方式启动（spawn），没有守卫会无限递归创建进程。
2. 进程间不共享内存，Pool.map的参数和返回值都要**可序列化**（pickle），传lambda、闭包、文件句柄会报错。

进程池高级一点的处理，用ProcessPoolExecutor（与ThreadPoolExecutor同一个API）：

```python
from concurrent.futures import ProcessPoolExecutor

def heavy(n):
    return sum(i * i for i in range(n))

if __name__ == "__main__":
    with ProcessPoolExecutor(max_workers=4) as pool:
        for result in pool.map(heavy, [10_000_000] * 4):
            print(result)
```

## 选择模型：一张决策表

| 任务类型          | 例子           | 方案                          | 原因                     |
| ----------------- | -------------- | ----------------------------- | ------------------------ |
| IO密集、中等并发 | 爬20个页面   | threading / 线程池            | 等待时让出GIL           |
| IO密集、高并发   | 千级并发请求   | asyncio（下一篇）             | 单线程事件循环，开销最小 |
| CPU密集          | 加密、批量计算 | multiprocessing / 进程池      | 绕开GIL，真多核         |
| 混合              | 爬取+解析      | 线程（IO）+ 进程池（CPU）组合 | 各用所长                 |

一句话记忆：**IO多用线程，CPU重用进程，高并发IO上asyncio**。

## 常见坑

1. **线程里抛异常没人知道**：直接用Thread时异常只打印到stderr，主线程无感。用ThreadPoolExecutor + future.result() 让异常传回主线程。

2. **daemon线程被强杀**：t.daemon = True的线程在主程序退出时直接终止，写一半的文件、事务会损坏。关键写操作不用daemon。
3. **锁忘了释放**：lock.acquire() 后异常跳过release。必须用with lock:。
4. **multiprocessing里闭包/lambda报错**：pickle序列化失败，把任务函数放模块顶层。
5. **join顺序**：先start全部再join全部，如果start一个join一个，就退化成串行了。
6. **进程池里的全局变量不共享**：每个子进程是独立副本，主进程改的变量子进程看不到，数据必须靠参数传入、结果返回。
