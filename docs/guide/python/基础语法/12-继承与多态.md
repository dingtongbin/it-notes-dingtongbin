﻿﻿﻿# 面向对象：继承与多态

继承解决"复用"，多态解决"统一调用不同实现"。这一篇讲清继承的机制、super的真实行为、什么时候不该用继承。

## 继承：复用与扩展

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        raise NotImplementedError("子类必须实现speak")

    def info(self):
        return f"我是 {self.name}"

class Dog(Animal):                    # Dog继承Animal
    def speak(self):
        return f"{self.name}: 汪汪"

class Cat(Animal):
    def __init__(self, name, indoor=True):    # 子类有新参数
        super().__init__(name)                # 把name的初始化委托给父类
        self.indoor = indoor

    def speak(self):
        return f"{self.name}: 喵"

d = Dog("旺财")
print(d.speak())     # 旺财: 汪汪（用的是Dog自己的）
print(d.info())      # 我是 旺财（用的是继承来的）
print(isinstance(d, Animal))    # True：Dog的实例"是一个" Animal
```

规则：

- 子类自动拥有父类的全部属性和方法（写一次，处处用）。
- 子类**重写（override）**同名方法，替换父类版本。
- 子类新增属性时，必须在 __init__ 里调用super().__init__(...)，否则父类的初始化逻辑（比如self.name = name）根本没执行，后面访问self.name抛AttributeError。

### super() 到底是什么super

不是"调用父类"，而是"沿MRO找下一个类"。单继承下两者看起来一样，多继承下有本质区别。

```python
class Base:
    def __init__(self):
        print("Base.__init__")

class A(Base):
    def __init__(self):
        print("A.__init__")
        super().__init__()

class B(Base):
    def __init__(self):
        print("B.__init__")
        super().__init__()

class C(A, B):          # 多继承
    def __init__(self):
        print("C.__init__")
        super().__init__()

C()
# C.__init__
# A.__init__
# B.__init__
# Base.__init__
```

如果A里写的是Base.__init__(self)（硬编码父类名），B的 __init__ 会被跳过。super的顺序由MRO决定：

```python
print([c.__name__ for c in C.__mro__])
# ['C', 'A', 'B', 'Base', 'object']
```

MRO（方法解析顺序）用C3线性化算法计算，保证每个类只出现一次、子类总在父类前、声明顺序保留。日常记住两条：单继承时super() 就是父类；多继承时写super() 别写死类名。

## 多态：同一接口，不同实现

```python
animals = [Dog("旺财"), Cat("咪咪"), Dog("大黄")]
for a in animals:
    print(a.speak())     # 不用管具体是Dog还是Cat，统一调speak
```

调用方只关心"会不会speak"，不关心它是什么类。这就是多态：**接口统一，实现各异**。

Python的多态更宽松——不要求继承关系，只要求对象有这个方法（鸭子类型）：

```python
class Robot:
    def speak(self):
        return "哔哔"

for a in [Dog("旺财"), Robot()]:
    print(a.speak())     # Robot没继承Animal也能进这个循环
```

"走起来像鸭子叫起来像鸭子，那它就是鸭子"。代价是没有编译期检查， duck typing出错是运行时AttributeError；所以现代Python用抽象基类或Protocol补上约束（见下文）。

## 抽象基类：强制子类实现

上面的raise NotImplementedError是手工版约束。标准做法用abc模块：

```python
from abc import ABC, abstractmethod

class Storage(ABC):
    @abstractmethod
    def save(self, key: str, value: bytes) -> None: ...

    @abstractmethod
    def load(self, key: str) -> bytes | None: ...

    # 抽象类可以有具体方法，子类直接继承
    def exists(self, key: str) -> bool:
        return self.load(key) is not None

class MemoryStorage(Storage):
    def __init__(self):
        self._data: dict[str, bytes] = {}

    def save(self, key, value):
        self._data[key] = value

    def load(self, key):
        return self._data.get(key)

class FileStorage(Storage):
    def __init__(self, root: str):
        self.root = root

    def save(self, key, value):
        with open(f"{self.root}/{key}", "wb") as f:
            f.write(value)

    def load(self, key):
        try:
            with open(f"{self.root}/{key}", "rb") as f:
                return f.read()
        except FileNotFoundError:
            return None

# storage = Storage()          # TypeError！抽象类不能实例化
store: Storage = MemoryStorage()   # 调用方面向抽象编程
    store.save("a", b"hello")
print(store.exists("a"))           # True
```

价值：调用方代码（store: Storage）完全不知道背后是内存还是文件，将来加OSS存储、Redis存储都不用改调用方。**面向接口编程**是多态的真正意义。

NotImplementedError版本和ABC版本的区别：ABC在实例化时就报错（早失败），NotImplementedError要等到调用那个方法才炸（晚失败）。库代码优先ABC。

## 继承的滥用与组合优先

继承的坑：耦合太深。父类一改，所有子类被动跟着变。

经典反面教材：需要"会飞的鸭子"时继承Duck加fly()，结果"不能飞的鸭子"也要被迫实现fly()。更好的做法是把"飞行"抽成组件：

```python
class FlyBehavior:
    def fly(self):
        print("扑腾翅膀")

class NoFly:
    def fly(self):
        print("我不会飞")

class Duck:
    def __init__(self, name, fly_behavior: FlyBehavior):
        self.name = name
        self.fly_behavior = fly_behavior     # 组合：行为作为属性注入
        def perform_fly(self):
        self.fly_behavior.fly()              # 委托给行为对象
        mallard = Duck("绿头鸭", FlyBehavior())
rubber = Duck("橡皮鸭", NoFly())
mallard.perform_fly()    # 扑腾翅膀
rubber.perform_fly()     # 我不会飞
```

经验法则：

- **is-a（是一个）用继承**：Dog是Animal，FileStorage是Storage。
- **has-a（有一个）用组合**：Duck有一个飞行行为，Car有一个引擎。
- 不确定时选组合，灵活且耦合低。"组合优于继承"是设计模式的总纲（03模块展开）。

继承层级控制在2~3层以内；超过4层的继承树，维护成本指数上升。

## object与内建继承

所有类最终继承object。所以才有 __str__、__eq__ 这些钩子可重写（下一篇展开）。实用继承场景还有：

```python
# 继承Exception做自定义异常（第12篇）
class AppError(Exception):
    pass

# 继承内置类型扩展行为class LoggedList(list):
    def append(self, item):
        print(f"append: {item}")
        super().append(item)

lst = LoggedList()
lst.append(1)     # append: 1
print(lst)        # [1]
```

继承内置类型基本可行，但某些内置方法内部不走子类的重写（比如C实现的dict.update不会调用子类的 __setitem__）；需要完全接管时用collections.UserDict/UserList。

## 常见坑

1. **子类 __init__ 忘调super**：父类属性没初始化，运行时AttributeError。写子类 __init__ 的第一行先想super。

2. **多继承写死父类名**：Base.__init__(self) 会破坏MRO链，一律super().__init__()。
3. **继承只为复用代码**：为省几行代码继承一个不相关的类，是设计事故的开端。复用优先考虑组合、函数、工具模块。
4. **isinstance滥用**：

```python
def area(shape):
    if isinstance(shape, Circle):
        return 3.14 * shape.r ** 2
    elif isinstance(shape, Square):
        return shape.side ** 2
# 每加一种形状就要改这个函数。让形状类各自实现area()，函数一行搞定：
def area(shape):
    return shape.area()
```

5. **菱形继承的意外行为**：两个父类有同名方法时，MRO决定谁被调用（声明顺序在前者优先）。多继承本身合法（Python允许），但Mixin才是多继承的正确姿势：功能单一的小类（如JSONSerializableMixin），主类多继承几个Mixin + 一个主基类。
