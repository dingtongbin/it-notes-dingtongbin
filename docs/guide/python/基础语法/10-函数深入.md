﻿﻿# 函数进阶：闭包与装饰器

装饰器是Python的招牌特性，Flask的 @app.route、pytest的 @pytest.fixture、FastAPI的路由装饰器全是它。装饰器建立在闭包之上，所以从闭包讲起。

## 复习：函数是对象

```python
def hi():
    print("hi")

print(type(hi))        # <class 'function'>，函数本身是个对象
alias = hi             # 可以赋值给变量（注意没有括号，加括号是调用）
alias()                # hi

del hi
alias()                # 名字删了，函数对象还活着，alias引用着它
```

## 闭包

内层函数引用了外层函数的变量，并且内层函数被返回或传出——这个"函数 + 它抓住的外层变量"的组合就是闭包。

```python
def make_greeter(greeting):
    def greet(name):
        return f"{greeting}, {name}"    # greet引用了外层的greeting
    return greet                        # 返回函数本身，没有括号
english = make_greeter("Hello")
chinese = make_greeter("你好")

print(english("tom"))    # Hello, tom
print(chinese("tom"))    # 你好，tom
```

make_greeter已经返回，它的局部变量greeting为什么还活着？因为greet函数对象通过 __closure__ 引用着它：

```python
print(english.__closure__[0].cell_contents)   # Hello
```

每个返回的greet都带着各自的greeting，所以english和chinese行为不同。**闭包 = 函数 + 它捕获的环境**，这是"函数工厂"模式。

带状态的闭包（nonlocal在这里正式登场）：

```python
def make_counter():
    count = 0
    def tick():
        nonlocal count       # 声明要改外层变量count += 1
        return count
    return tick

c1 = make_counter()
c2 = make_counter()
print(c1(), c1(), c1())   # 1 2 3
print(c2())               # 1，每个闭包独立
```

应用场景：计数器、缓存、回调、重试包装。类能做的事闭包也能做（反之亦然），轻量状态用闭包，多方法重状态用类。

## 装饰器

### 需求引入

想给一批函数统一加上"计时"功能，又不想改它们的代码：

```python
import time

def slow_add(a, b):
    time.sleep(0.1)
    return a + b

# 不用装饰器的手工版本
def timed_add(a, b):
    start = time.perf_counter()
    result = slow_add(a, b)
    print(f"耗时 {time.perf_counter() - start:.3f}s")
    return result

print(timed_add(1, 2))
```

每个函数都包一层太蠢。观察timed_add的结构：接收原函数、返回新函数——这就是装饰器：

```python
import time
import functools

def timed(func):
    @functools.wraps(func)          # 后文解释，先记住加上
def wrapper(*args, **kwargs):   # 万能签名，接住任意参数
    start = time.perf_counter()
        result = func(*args, **kwargs)   # 调用原函数
        print(f"{func.__name__} 耗时 {time.perf_counter() - start:.3f}s")
        return result
    return wrapper

@timed                                # 语法糖
def slow_add(a, b):
    time.sleep(0.1)
    return a + b

print(slow_add(1, 2))
```

@timed完全等价于：

```python
def slow_add(a, b):
    time.sleep(0.1)
    return a + b
slow_add = timed(slow_add)
```

slow_add这个名字现在指向wrapper，wrapper内部又引用着原函数，调用它 = 计时 + 原逻辑 + 打印。**装饰器是接收函数并返回函数的函数**，@ 只是让语法更好看。

### functools.wraps的作用

不加wraps的后果：

```python
print(slow_add.__name__)   # 不加wraps时输出 "wrapper"
print(slow_add.__doc__)    # None
```

函数的元信息（名字、文档）被wrapper覆盖，日志、调试、文档生成全部失真。@functools.wraps(func) 把原函数的元信息拷贝到wrapper上。**写装饰器必加**，面试也爱问。

### 带参数的装饰器（三层嵌套）

需求：可配置的装饰器，如 @repeat(times=3)。注意语法多了一层：

```python
import functools

def repeat(times):
    def decorator(func):                 # 真正的装饰器
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(times=3)          # 先执行repeat(times=3) 得到decorator，再 @decorator
def greet(name):
    print(f"hi {name}")

greet("tom")              # 打印3次
```

调用顺序拆解：greet = repeat(times=3)(greet)。为什么必须三层？因为 @ 后面跟的表达式先求值——repeat(times=3) 求值结果是装饰器decorator。

辨析两种写法：

```python
@timed            # 直接 @装饰器def f(): ...

@repeat(times=3)  # @装饰器工厂(...)
def g(): ...
```

### 实用装饰器示例

重试装饰器（运维场景直接能用）：

```python
import time
import functools

def retry(times=3, delay=1.0, exceptions=(Exception,)):
    """失败自动重试。exceptions限定只捕获特定异常。"""
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            last_exc = None
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except exceptions as e:
                    last_exc = e
                    print(f"{func.__name__} 第 {attempt} 次失败: {e}")
                    if attempt < times:
                        time.sleep(delay)
            raise last_exc       # 重试耗尽，抛最后一次的异常return wrapper
    return decorator

@retry(times=3, delay=0.5, exceptions=(ConnectionError, TimeoutError))
def fetch_data():
    import random
    if random.random() < 0.7:
        raise ConnectionError("网络不稳")
    return {"ok": True}

print(fetch_data())
```

缓存装饰器（不用functools.lru_cache，手写理解原理）：

```python
def memoize(func):
    cache = {}
    @functools.wraps(func)
    def wrapper(*args):
        if args not in cache:
            cache[args] = func(*args)
        return cache[args]
    return wrapper

@memoize
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(50))    # 无缓存是指数级耗时，加缓存瞬间出结果
```

标准库自带functools.lru_cache，生产直接用它（支持maxsize、缓存信息统计）：

```python
import functools

@functools.lru_cache(maxsize=128)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)
print(fib(200))
print(fib.cache_info())     # CacheInfo(hits=..., misses=..., maxsize=128, currsize=...)
```

注意：lru_cache的参数必须可哈希，传list会报错。

### 类装饰器与多层装饰器（了解）

装饰器也可以是类（实现 __call__）；一个函数可以叠多个装饰器，执行顺序自下而上：

```python
@timed
@retry(times=2)
def task(): ...

# 等价于task = timed(retry(times=2)(task))
# 先包retry再包timed，所以timed在最外层，计时包含重试时间
```

## 常见坑

**忘写functools.wraps**：函数名变wrapper，日志里分不清谁是谁。

**装饰器只在导入时执行一次**：@repeat(times=3) 的times在定义时固定，运行期改不了；需要动态配置就传函数参数而不是装饰器参数。

**被装饰的函数丢失签名**：wrapper的 *args, **kwargs让IDE/文档看不到真实参数。用inspect.signature或functools.wraps缓解；参数要求严格的库用typing.ParamSpec（3.10+）：

```python
import functools
import typing

P = typing.ParamSpec("P")
R = typing.TypeVar("R")

def timed(func: typing.Callable[P, R]) -> typing.Callable[P, R]:
    @functools.wraps(func)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} 耗时 {time.perf_counter() - start:.3f}s")
        return result
    return wrapper
```

**装饰有返回值的函数忘了return**：wrapper里漏掉return result，调用方拿到None。排查这类bug的口诀：装饰后函数"返回None"先查wrapper的return。

**闭包捕获循环变量**：第7篇讲过lambda: i的坑，闭包同理。
