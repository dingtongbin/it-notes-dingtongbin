﻿﻿# 模块、包与虚拟环境

一个 .py文件是一个模块（module），装模块的目录是包（package）。这一篇讲import的真实机制、项目结构规范、虚拟环境的工程实践——从"能跑"到"像专业项目"的分水岭。

## 模块：复用的基本单元

### import的四种形式

```python
import os                        # 导入整个模块，用os.path
import os.path as osp            # 起别名
from os import path              # 只导入模块里的某个名字
from pathlib import Path, PurePath   # 导入多个
```

选择标准：

- 标准库和第三方库：import module或from package import module都常见。
- **不要from module import ***：污染当前命名空间，来源不可追溯，唯一例外是交互式调试。
- 循环引用（A import B、B import A）大多源于设计问题，先抽公共部分到第三个模块。

### import时发生了什么import mymodule的执行过程：

1. 按sys.path里的路径列表搜索mymodule.py（或包目录）。
2. 找到后**从头到尾执行一遍**模块代码（这就是模块级代码会执行的原理）。
3. 生成模块对象放进sys.modules缓存；再次import直接命中缓存，**不会重复执行**。

验证：

```python
# counter.py
print("counter模块被执行了")
count = 0
```

```python
import counter
import counter          # 第二次导入无输出：命中缓存
print(counter.count)
```

副作用：模块级代码（打印、连数据库、读配置）在import时执行。所以模块级只放定义和常量，动作放函数里。

### __name__ == "__main__" 的真相

每个模块都有 __name__ 属性：被import时是模块名，**直接运行时是 "__main__"**：

```python
# utils.py
def add(a, b):
    return a + b

if __name__ == "__main__":
    # 只有python utils.py直接运行才走到这里
    # 被import时不会执行——测试代码、示例代码放这里
    print(add(1, 2))
```

这就是"既当库用、又能直接跑测试"的标准写法。所有 .py文件的底部都该有这个守卫。

## 包：带组织的模块目录

### 包结构

```
myproject/
├── app/
│   ├── __init__.py          # 有它才是"常规包"（3.3+ 可省略，但写上最稳）
│   ├── core.py
│   └── utils/
│       ├── __init__.py
│       └── format.py
├── main.py
└── requirements.txt
```

```python
# main.py里
from app.core import function_a        # 完整路径：包.子包.模块.名字
from app.utils.format import fmt_time
import app.core as core                # 也可以导入模块本身
```

import搜索从sys.path的第一个条目开始，运行python main.py时，main.py所在目录（myproject/）自动加入sys.path，所以from app... 能找到。

### __init__.py：包的门面

```python
# app/__init__.py
from app.core import function_a     # 提升接口：调用方可以
from app import function_a

__all__ = ["function_a"]            # 声明公开接口（from app import * 时只导出这些）

__version__ = "1.0.0"
```

__all__ 的作用：定义from x import * 的导出范围，也是给读者的"这是公开API"声明。

### 相对导入（包内部）

```python
# app/core.py里想用app/utils/format.py
from app.utils.format import fmt_time    # 绝对导入（推荐，清晰）
from .utils.format import fmt_time       # 相对导入：. 是当前包from ..other import x                    # .. 是上一级包
```

注意：含相对导入的模块**不能直接运行**（python app/core.py报attempted relative import），要么python -m app.core（以模块方式运行），要么全用绝对导入。初学阶段统一用绝对导入。

### sys.path与运行方式

```python
import sys
print(sys.path)
```

Python按这个列表找模块：脚本所在目录 → PYTHONPATH → 环境安装的site-packages。常见坑：从别的目录运行脚本，找不到自己项目里的包。解决：

- 在项目根目录运行：python -m app.core（-m以模块方式运行，项目根自动进sys.path）。
- 或安装为可编辑包：pip install -e .（需要pyproject.toml）。

## 项目结构规范（后端项目标准布局）

```
myproject/
├── pyproject.toml            # 项目元数据与依赖声明（现代标准）
├── requirements.txt          # 锁定依赖（或用uv.lock）
├── README.md
├── .gitignore
├── src/
│   └── myapp/
│       ├── __init__.py
│       ├── main.py           # 入口
│       ├── config.py         # 配置
│       ├── models.py         # 数据模型
│       ├── api/              # 接口层
│       │   └── routes.py
│       ├── services/         # 业务逻辑层
│       │   └── order.py
│       └── db/               # 数据访问层
│           └── session.py
├── tests/
│   ├── test_order.py
│   └── conftest.py
└── scripts/                  # 运维脚本
    └── backup.py
```

分层规则：api层只做参数校验和调用services；services装业务逻辑；db层管数据库会话。依赖单向：api → services → db，禁止反向。

## 虚拟环境工程实践

第1篇学了venv基本用法，这里补齐团队协作流程：

```bash
# 新同事拿到项目后的标准动作git clone <repo>
cd myproject
python -m venv .venv
.venv\Scripts\activate        # Windows
pip install -r requirements.txt
python -m src.myapp.main      # 或安装后直接跑入口
```

依赖管理的两层文件：

- pyproject.toml：声明直接依赖（项目需要什么）。
- requirements.txt（或lock文件）：锁定精确版本（可复现环境）。

pyproject.toml最小示例：

```toml
[project]
name = "myapp"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = [
    "fastapi>=0.115",
    "uvicorn[standard]>=0.30",
    "sqlalchemy>=2.0",
]

[project.optional-dependencies]
dev = ["pytest>=8.0", "ruff>=0.6"]
```

pip install -e .[dev] 即可安装项目本体 + 开发工具。

.env不进git（.gitignore里写明），进git的是 .env.example（只有键名没有值）。

## 常见坑

1. **ModuleNotFoundError但文件明明在**：sys.path不包含那个目录。从项目根运行、或用 -m方式。

2. **文件名与库名冲突**：写了个email.py，标准库email就被你的文件顶掉，import email拿到的是你的文件。命名避开标准库名。
3. **pip装错环境**：多环境并存时pip install可能进别的Python。永远python -m pip install。
4. **循环导入**：报ImportError: cannot import name ...（部分初始化的模块）。解法：合并模块、延迟导入（函数内import）、抽取公共依赖。
5. **__init__.py里塞大量逻辑**：init应轻，只有版本号和接口提升；重逻辑会让import变慢且易循环依赖。
6. **虚拟环境进git**：.venv/ 必须写进 .gitignore。
