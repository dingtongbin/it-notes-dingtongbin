﻿﻿# 面向对象：魔法方法与属性控制

魔法方法（dunder methods，双下划线包裹）是Python对象行为的钩子：len(obj)、obj == other、print(obj)、obj[0] 背后全是对应魔法方法的调用。掌握它们，你的类就能自然融入Python语言体系。

## 核心认知：语法糖背后的协议

```python
lst = [1, 2]
print(len(lst))        # 2
print(lst.__len__())   # 2，len() 的真身print(lst == [1, 2])   # True
print(lst.__eq__([1, 2]))   # == 的真身print(lst + [3])       # [1, 2, 3]
print(lst.__add__([3]))   # + 的真身
```

内置函数和运算符只是语法糖，真正干活的是对象上的魔法方法。你重写它们，就是自定义对象在该操作下的行为。

## 必会魔法方法

### 对象表示：__repr__ 与 __str__

```python
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):
        return f"Point({self.x!r}, {self.y!r})"    # !r表示用repr嵌套
    def __str__(self):
        return f"({self.x}, {self.y})"

p = Point(3, 4)
print(p)            # (3, 4)，print/str() 走 __str__
print(repr(p))      # Point(3, 4)，repr()/调试器/容器内走 __repr__
print([p])          # [Point(3, 4)]，容器里的元素用 __repr__
```

区别与用途：

- __repr__：给开发者看的，目标是无歧义，理想标准是eval(repr(obj)) == obj。
- __str__：给用户看的，追求易读。

只写 __repr__ 时，str() 会退回用它，所以**偷懒策略：优先实现 __repr__**。

### 相等与哈希：__eq__ 与 __hash__

```python
class User:
    def __init__(self, uid, name):
        self.uid, self.name = uid, name

    def __eq__(self, other):
        if not isinstance(other, User):
            return NotImplemented          # 让Python回退尝试
        other.__eq__
        return self.uid == other.uid       # 业务上uid相同就算同一个用户
    def __hash__(self):
        return hash(self.uid)              # 必须与 __eq__ 一致：相等的对象哈希必须相等
    u1, u2 = User(1, "tom"), User(1, "tom2")
print(u1 == u2)               # True
users = {u1: "管理员"}
print(users[u2])              # 管理员，u2能查到u1存的值，因为哈希和相等都一致
```

铁律：**重写 __eq__ 必须同时重写 __hash__**（相等的对象必须同哈希），否则放进dict/set后行为诡异。只读 __eq__ 不定义 __hash__ 的话，实例会变成不可哈希（无法做字典键）。

### 算术运算：__add__ 等

```python
class Money:
    def __init__(self, amount: float, currency: str = "CNY"):
        self.amount, self.currency = amount, currency

    def __add__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        if self.currency != other.currency:
            raise ValueError("币种不同不能相加")
        return Money(self.amount + other.amount, self.currency)

    def __repr__(self):
        return f"Money({self.amount:.2f}, '{self.currency}')"

a = Money(10.5) + Money(20.25)
print(a)              # Money(30.75, 'CNY')
# a + 5               # 返回NotImplemented后Python依次尝试Money.__radd__、报TypeError
```

常用算术钩子：__add__/__sub__/__mul__/__truediv__（+ - * /）、__radd__ 等反向版本（左操作数不支持时调用）、__iadd__（+=，不定义则退回 __add__ 再赋值）。

### 容器协议：__len__/__getitem__/__iter__/__contains__

```python
class Playlist:
    def __init__(self, songs: list[str]):
        self._songs = songs

    def __len__(self):
        return len(self._songs)

    def __getitem__(self, index: int | slice):
        return self._songs[index]        # 顺手支持切片
    def __contains__(self, song: str) -> bool:
        return song in self._songs

    def __iter__(self):
        return iter(self._songs)         # 有了它，for循环直接可用pl = Playlist(["晴天", "七里香"])
print(len(pl))          # 2
print(pl[0])            # 晴天print("晴天" in pl)     # True
for s in pl:            # 走 __iter__
    print(s)
```

实现这几个方法后，你的对象就能用len()、[]、in、for循环——像内置类型一样工作。

### 上下文管理：__enter__/__exit__（with语句的真身）

```python
import time

class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self                  # 返回值绑定给as后面的变量
    def __exit__(self, exc_type, exc_val, exc_tb):
        self.elapsed = time.perf_counter() - self.start
        print(f"耗时 {self.elapsed:.3f}s")
        return False                 # False=异常继续传播；True=吞掉异常（慎用）

with Timer() as t:
    sum(range(1_000_000))
# 耗时0.0xx s
```

with保证 __exit__ 一定执行（即使内部抛异常），这就是文件、锁、连接都用with的原因：资源释放不依赖开发者记得关闭。实现自己的资源类时，配合contextlib更省事：

```python
from contextlib import contextmanager

@contextmanager
def timer():
    start = time.perf_counter()
    try:
        yield                       # yield前是 __enter__，后是 __exit__
    finally:
        print(f"耗时 {time.perf_counter() - start:.3f}s")

with timer():
    sum(range(1_000_000))
```

## 属性控制

### @property：把方法伪装成属性

需求：balance修改要走校验，但又想让调用方写acc.balance而不是acc.get_balance()：

```python
class Account:
    def __init__(self, balance: float):
        self._balance = balance          # 内部存 _balance

    @property
    def balance(self) -> float:          # 读：acc.balance自动调用它
        return self._balance

    @balance.setter
    def balance(self, value: float):     # 写：acc.balance = x自动调用它
        if value < 0:
            raise ValueError("余额不能为负")
        self._balance = value

acc = Account(100)
print(acc.balance)        # 100，看起来像属性，实际走getter
acc.balance = 500         # 走setter，带校验
print(acc.balance)
acc.balance = -1          # ValueError: 余额不能为负
```

价值：**接口不用改**。一开始直接暴露self.balance，后来需要校验时加property，调用方代码一行不改。这就是"先写属性、需要时升级property"的重构路径。

只读属性：只定义getter不定义setter，赋值即报AttributeError。

### __getattr__ 与 __getattribute__

```python
class LazyConfig:
    def __init__(self):
        self._data = {}

    def __getattr__(self, name):
        """只在常规查找失败时调用——懒加载钩子。"""
        print(f"懒加载 {name}")
        self._data[name] = f"<{name} 的值>"
        return self._data[name]

cfg = LazyConfig()
print(cfg.db_host)    # 懒加载db_host -> <db_host的值>；第二次访问不再触发
```

- __getattr__(name)：常规查找（实例/类/父类）都失败时兜底调用。
- __getattribute__(name)：**所有**属性访问都经过它，拦截一切；写错容易无限递归（内部要用object.__getattribute__(self, name) 访问属性），新手别碰，知道存在即可。

__setattr__ 拦截所有赋值，同样有递归风险（内部要用object.__setattr__）。动态代理、ORM字段映射（Django Model的字段）底层就是这几个钩子。

### __slots__：限制属性、省内存

```python
class Point:
    __slots__ = ("x", "y")           # 声明后实例只能有这两个属性
    def __init__(self, x, y):
        self.x, self.y = x, y

p = Point(1, 2)
# p.z = 3        # AttributeError！拼错属性名当场报错而不是静默创建
```

两个用途：

1. 拼错属性名立刻暴露（否则self.nmae = x静默创建新属性，bug藏到深处）。
2. 省内存：取消每个实例的 __dict__，百万级小对象内存可省一半以上。数据字段固定的类（如解析出的百万条记录）值得加。

## 综合实例：一个"像内置类型"的库存类

```python
from dataclasses import dataclass, field

@dataclass
class Product:
    sku: str
    price: float

class Inventory:
    def __init__(self):
        self._items: dict[str, int] = {}

    def add(self, product: Product, qty: int = 1) -> None:
        self._items[product.sku] = self._items.get(product.sku, 0) + qty

    def __getitem__(self, sku: str) -> int:
        return self._items.get(sku, 0)          # 不存在的SKU返回0而不是报错
    def __contains__(self, sku: str) -> bool:
        return sku in self._items

    def __len__(self) -> int:
        return len(self._items)

    def __iter__(self):
        return iter(self._items)

inv = Inventory()
inv.add(Product("A1", 10.0), 3)
inv.add(Product("B2", 5.0))

print(inv["A1"])        # 3
print("B2" in inv)      # True
print(len(inv))         # 2
for sku in inv:
    print(sku, inv[sku])
```

## 常见坑

1. **__eq__ 返回NotImplemented而不是False**：False会终结比较，NotImplemented让Python去尝试对方的方法。类型不同的比较返回NotImplemented是标准做法。

2. **重写 __eq__ 忘 __hash__**：对象无法放进set/dict。
3. **__getattr__ 里访问不存在的self属性导致递归**：比如在 __getattr__ 里写self._data而 _data恰好没初始化，再次触发 __getattr__，无限递归。__init__ 里先建好所有内部属性。
4. **property setter忘了给内部属性赋值**：校验半天self._balance没更新，读回来永远是旧值。
5. **__enter__ 忘记return self**：with Timer() as t: 里t是None。
6. **__exit__ 返回True吞异常**：调试时发现"异常怎么消失了"，先查上下文管理器的返回值。
