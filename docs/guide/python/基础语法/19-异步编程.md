﻿﻿# 异步编程asyncio

asyncio是Python的高并发IO方案：单线程内成千上万个任务"同时"等待。FastAPI的异步接口、aiohttp爬虫、异步数据库驱动全建立在它之上。这一篇从"为什么需要异步"讲到协程的正确写法和常见陷阱。

## 为什么需要异步

回顾第16篇：IO等待期间线程会阻塞。多线程能解决，但线程有成本——每个线程约8MB栈内存、上下文切换开销，1万个并发连接 = 1万个线程，服务器扛不住。

异步的思路：**等待发生时主动让出控制权**，让别的任务用CPU；等待结束后再回来继续。这一切发生在单线程里，切换由程序自己控制（不是操作系统强切），因此：

- 一个线程就能挂起几万个任务（每个协程只是函数调用帧 + 一个状态对象，KB级）。
- 没有线程切换的抢占，**协程之间默认没有竞态问题**（但仍要小心共享资源的操作顺序）。

适用判断：任务是"等网络/等磁盘/等数据库"（IO密集）→ asyncio；任务是"纯计算"（CPU密集）→ asyncio毫无帮助，单线程反而串行化了，用multiprocessing。

## 协程、await、事件循环

### 第一个例子

```python
import asyncio

async def fetch(name: str, delay: float) -> str:
    """async def定义的是协程函数。"""
    print(f"{name} 开始")
    await asyncio.sleep(delay)      # 模拟IO等待，等待期间让出控制权
    print(f"{name} 结束")
    return f"{name} 的结果"

async def main():
    # 方式一：顺序执行（没有并发，只是语法不同）
    r1 = await fetch("A", 1.0)
    r2 = await fetch("B", 1.0)
    print(r1, r2)

    # 方式二：gather并发执行
    results = await asyncio.gather(
        fetch("C", 1.0),
        fetch("D", 2.0),
        fetch("E", 1.5),
    )
    print(results)

start = asyncio.get_event_loop().time()
asyncio.run(main())                 # 程序入口：创建事件循环并运行main
```

三个要点：

1. async def定义协程函数。**调用它不会执行函数体**，只返回协程对象——和生成器一样惰性。
2. await协程 才真正执行它，且执行到它内部的下一个await点时可能切换。
3. asyncio.run(main()) 是程序入口：创建事件循环（event loop），跑完main后关闭循环。

只有协程/可等待对象才能被await。普通函数调用（time.sleep(1)）不能await——并且**协程里绝不能用阻塞调用**（见第6节）。

### 时间线对比gather版本的执行时间线（三个任务共2秒而非4.5秒）：

```
C: ──开始──────────结束(1.0s)
D: ──开始────────────────────结束(2.0s)
E: ──开始──────────────结束(1.5s)
总耗时 = max(1.0, 2.0, 1.5) = 2.0s
```

await asyncio.sleep(1.0) 的时候，事件循环去跑D和E了——等待被重叠，这就是全部秘密。

## 任务：

并发执行的调度单位gather够用但不够灵活。asyncio.create_task把协程包装成Task，立即调度执行：

```python
import asyncio

async def worker(name: str, delay: float):
    await asyncio.sleep(delay)
    return f"{name} 完成"

async def main():
    # create_task立即开始调度（不用等await它）
    t1 = asyncio.create_task(worker("A", 1.0))
    t2 = asyncio.create_task(worker("B", 0.5))

    # 中间可以做别的事，任务在后台跑
    print("任务已提交")

    r1 = await t1        # 等待任务完成并取结果r2 = await t2
    print(r1, r2)

asyncio.run(main())
```

Task的价值：**先提交，后收集**。适合"同时发起一批请求，期间穿插其他逻辑"的场景。

### gather的错误处理

```python
import asyncio

async def ok():
    await asyncio.sleep(0.1)
    return "成功"

async def bad():
    await asyncio.sleep(0.05)
    raise ValueError("炸了")

async def main():
    # 默认：一个任务抛异常，gather立即抛出，但其他任务仍在后台跑（要小心）
    try:
        await asyncio.gather(ok(), bad())
    except ValueError as e:
        print(f"捕获: {e}")

    # return_exceptions=True：异常当结果返回，不中断其他任务
    results = await asyncio.gather(ok(), bad(), return_exceptions=True)
    print(results)      # ['成功', ValueError('炸了')]
    for r in results:
        if isinstance(r, Exception):
            print(f"任务失败: {r}")

asyncio.run(main())
```

### 超时控制

```python
import asyncio

async def slow():
    await asyncio.sleep(10)
    return "太晚了"

async def main():
    # Python 3.11+ 推荐
    TaskGroup + timeout上下文try:
        async with asyncio.timeout(2.0):       # 3.11+
            print(await slow())
    except TimeoutError:
        print("2秒内没完成，放弃")

    # 老写法：wait_for（兼容所有版本，仍然常用）
    try:
        print(await asyncio.wait_for(slow(), timeout=2.0))
    except asyncio.TimeoutError:
        print("wait_for超时")

asyncio.run(main())
```

Python 3.11+ 的TaskGroup是更安全的批量管理（一个失败会自动取消其余，保证没有任务泄漏）：

```python
async def main():
    async with asyncio.TaskGroup() as tg:      # 3.11+
        t1 = tg.create_task(worker("A", 1.0))
        t2 = tg.create_task(worker("B", 2.0))
    # 离开with块时所有任务都已完成；任一抛异常则抛ExceptionGroup
    print(t1.result(), t2.result())
```

新项目优先TaskGroup；gather继续能用，老代码里大量存在。

### 并发限制：

信号量1万个URL直接gather会打爆目标服务器。用Semaphore限流：

```python
import asyncio

async def fetch(url: str, sem: asyncio.Semaphore):
    async with sem:                     # 最多10个并发进入
        await asyncio.sleep(1)
        return url

async def main():
    sem = asyncio.Semaphore(10)
    urls = [f"https://api.example.com/{i}" for i in range(100)]
    results = await asyncio.gather(*(fetch(u, sem) for u in urls))
    print(len(results))

asyncio.run(main())
```

## 异步上下文管理器与异步迭代器

```python
# 异步with：资源获取本身要等待时用（如数据库连接池）
class AsyncConn:
    async def __aenter__(self):
        await asyncio.sleep(0.1)        # 模拟建连
        print("连接已建立")
        return self

    async def __aexit__(self, *exc):
        await asyncio.sleep(0.1)
        print("连接已关闭")

async def main():
    async with AsyncConn() as conn:
        print("使用连接")

# 异步for：数据本身按块到达时用（如流式响应、分页拉取）
async def pages():
    for i in range(3):
        await asyncio.sleep(0.1)
        yield f"第 {i} 页"              # async generator

async def main2():
    async for page in pages():
        print(page)

asyncio.run(main2())
```

标准协议名记忆：同步的 __enter__/__iter__ 加个a变成 __aenter__/__aiter__。

## 异步HTTP客户端：

aiohttp / httpx异步生态的入口。httpx同时支持同步和异步，API与requests几乎一致，推荐：

```bash
pip install httpx
```

```python
import asyncio
import httpx

async def fetch(client: httpx.AsyncClient, url: str) -> tuple[str, int]:
    resp = await client.get(url)
    return url, resp.status_code

async def main():
    urls = ["https://httpbin.org/delay/1"] * 5
    async with httpx.AsyncClient(timeout=10) as client:      # 异步上下文管理客户端
        results = await asyncio.gather(*(fetch(client, u) for u in urls))
    for url, code in results:
        print(url, code)

asyncio.run(main())
```

批量并发抓取的完整模板（限流 + 超时 + 错误处理）：

```python
import asyncio
import httpx

async def fetch_one(client, url, sem):
    async with sem:
        try:
            resp = await client.get(url)
            resp.raise_for_status()
            return url, resp.json()
        except httpx.HTTPStatusError as e:
            return url, f"HTTP {e.response.status_code}"
        except httpx.RequestError as e:
            return url, f"网络错误 {type(e).__name__}"

async def crawl(urls):
    sem = asyncio.Semaphore(5)
    async with httpx.AsyncClient(timeout=10) as client:
        return await asyncio.gather(*(fetch_one(client, u, sem) for u in urls))

if __name__ == "__main__":
    results = asyncio.run(crawl([f"https://httpbin.org/status/200" for _ in range(10)]))
    for url, data in results:
        print(url, type(data).__name__)
```

## 最重要的纪律：协程里不许阻塞

事件循环是单线程的。协程里任何一个**同步阻塞调用**（time.sleep、requests、pymysql、文件大IO、time.sleep）都会卡住整个循环，所有并发任务一起冻结：

```python
import asyncio
import time

async def bad():
    time.sleep(2)          # 灾难：整个事件循环停摆2秒，其他任务全部卡死
    async def good():
    await asyncio.sleep(2)  # 正确：让出控制权

# 确实要跑阻塞代码时，丢到线程池：
async def blocking_in_thread():
    loop = asyncio.get_running_loop()
    result = await loop.run_in_executor(None, time.sleep, 2)   # None=默认线程池
    # 或用装饰器语法（3.9+）：
    await asyncio.to_thread(time.sleep, 2)                     # 推荐，简单直接
```

记住三个逃生通道：

- await asyncio.to_thread(阻塞函数, 参数)：把阻塞调用扔进线程池（3.9+，首选）。
- loop.run_in_executor(pool, func, *args)：老写法，可控线程池。
- 异步库里找替代品：requests → httpx/aiohttp；pymysql → asyncmy/aiomysql；redis-py自带异步模式。

FastAPI场景的对应规则：async def路由里禁止同步阻塞（用await异步库）；写不了异步库就干脆定义成普通def路由——FastAPI会自动把它丢进线程池执行，不会卡事件循环。

## 常见坑

1. **忘了await**：fetch(...) 单独一行只创建协程不执行，还伴随RuntimeWarning: coroutine was never awaited。看到这个警告就是漏了await。

2. **在协程里用time.sleep / requests**：全局卡死，见第6节。症状通常是"并发怎么退化成串行了"。
3. **asyncio.run里再嵌asyncio.run**：一个进程的事件循环一般只有一个，嵌套运行报RuntimeError。把main设计成唯一的asyncio.run入口。
4. **Jupyter里asyncio.run报错**：notebook自己跑着事件循环，用await main() 直接顶层等待即可。
5. **CPU密集任务用asyncio**：没有await点的事件循环无法切换，一个死循环计算任务冻结一切。CPU任务丢进程池loop.run_in_executor(process_pool, ...)。
6. **Task引用被垃圾回收**：asyncio.create_task(coro()) 返回的Task如果不保存引用，可能被GC中途取消。规范：保存到集合或变量，完成后pop。
