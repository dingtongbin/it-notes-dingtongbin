﻿﻿# 面向对象：类与实例

面向对象（OOP）不是"必须有"的语法，而是组织复杂代码的手段。这一篇从"没有类时怎么办"讲起，把类、实例、属性、方法一次讲透。

## 为什么需要类

管理100个用户，每个用户有名字、年龄、邮箱，还有"打招呼""判断成年"两个行为。用字典：

```python
users = [
    {"name": "tom", "age": 25, "email": "tom@x.com"},
    {"name": "jerry", "age": 15, "email": "jerry@x.com"},
]

def greet(user):
    return f"你好，{user['name']}"

def is_adult(user):
    return user["age"] >= 18
```

能用，但有两个隐患：一是数据和行为分离，greet/is_adult散落在外，找逻辑要翻遍文件；二是没有约束，user["age"] = "abc" 这种脏数据悄悄混进来，出错的地方可能在千里之外。

类把数据（属性）和行为（方法）绑在一起：

```python
class User:
    def __init__(self, name, age, email):
        self.name = name
        self.age = age
        self.email = email

    def greet(self):
        return f"你好，{self.name}"

    def is_adult(self):
        return self.age >= 18

u = User("tom", 25, "tom@x.com")
print(u.greet())       # 你好，tom
print(u.is_adult())    # True
```

## 类的定义与实例化

```python
class Dog:
    """一只狗。"""

    kind = "犬科"              # 类属性：属于类，所有实例共享
    def __init__(self, name, age):
        """初始化方法：创建实例时自动调用。"""
        self.name = age        # 实例属性：属于每个实例
        self.age = 25          # 故意写错演示：name=age, age=25，见下文d = Dog("旺财", 3)
print(d.name)     # 3 ！__init__ 里self.name = age写反了，值错位
print(d.age)      # 3... 注意这里实际是25
```

逐个拆解：

- class Dog: 定义类，类名约定大驼峰（PascalCase）。
- __init__ 不是构造函数本身（构造是Dog(...) 触发的 __new__），而是**初始化方法**：实例刚创建好，把参数交给它配置实例。
- self指当前实例。d.greet() 的真实过程是Dog.greet(d)——Python把实例方法转成"类的函数 + 实例当第一个参数"。self这个名字只是约定，但它雷打不动地占第一个参数位。
- 忘写self是新手第一大错误：def greet(): 然后d.greet() 报TypeError: Dog.greet() takes 0 positional arguments but 1 was given——1就是Python自动传进去的实例本身。

### 实例属性vs类属性

```python
class Dog:
    kind = "犬科"              # 类属性
    count = 0

    def __init__(self, name):
        self.name = name       # 实例属性
        Dog.count += 1         # 统计创建了多少只（读类属性用类名）

a, b = Dog("a"), Dog("b")
print(a.kind, b.kind, Dog.kind)   # 犬科 犬科 犬科，共享
print(Dog.count)                  # 2

a.kind = "自定义"                  # 注意！这是给实例a新建了实例属性，遮住类属性
print(a.kind, b.kind)             # 自定义 犬科Dog.kind = "修改后"
print(b.kind)                     # 修改后，b自己没有kind，按类找
```

查找顺序：**实例属性优先，找不到再找类属性，再往父类找**。a.kind = "自定义" 创建的是a自己的属性，不影响别的实例。

类属性的合理用途：所有实例共享的常量、配置、计数器；实例的个体状态一律放实例属性（在 __init__ 里赋值）。

### 一个完整例子：订单类

```python
class Order:
    status_pending = "pending"
    status_paid = "paid"

    def __init__(self, order_id: str, items: list[tuple[str, float]]):
        self.order_id = order_id
        self.items = items            # [(商品名, 价格), ...]
        self.status = Order.status_pending

    def total(self) -> float:
        return sum(price for _, price in self.items)

    def pay(self) -> bool:
        if self.status != Order.status_pending:
            print("只能对待支付订单付款")
            return False
        self.status = Order.status_paid
        return True

order = Order("A001", [("键盘", 199.0), ("鼠标", 89.0)])
print(order.total())     # 288.0
order.pay()
order.pay()              # 只能对待支付订单付款
```

## 方法类型：实例方法、类方法、静态方法

```python
class Date:
    def __init__(self, year, month, day):
        self.year, self.month, self.day = year, month, day

    # 实例方法：第一个参数self，操作实例
    def show(self):
        return f"{self.year}-{self.month:02d}-{self.day:02d}"

    # 类方法：第一个参数cls（类本身），常用于"替代构造器"
    @classmethod
    def from_string(cls, s: str) -> "Date":
        y, m, d = map(int, s.split("-"))
        return cls(y, m, d)           # cls(y,m,d) 等价Date(y,m,d)，且子类调用时会构造子类

    # 静态方法：没有self/cls，只是逻辑上归属这个类的普通函数
    @staticmethod
    def is_leap(year: int) -> bool:
        return year % 4 == 0 and (year % 100 != 0 or year % 400 == 0)

d = Date(2024, 8, 30)
print(d.show())
d2 = Date.from_string("2026-01-15")    # 类方法当第二构造器用print(d2.show())
print(Date.is_leap(2024))              # True
```

选择标准：碰实例数据用实例方法；需要"以别的方式构造实例"用类方法；和实例无关只是放在类里的工具函数用静态方法。

## 封装：Python的"约定"式私有

其他语言有private关键字，Python用约定：

```python
class Account:
    def __init__(self, owner, balance):
        self.owner = owner
        self._balance = balance        # 单下划线：约定"内部使用"，外部别碰（但想碰也能碰）
        self.__pin = "1234"            # 双下划线：名称改写（name mangling）

    def deposit(self, amount: float):
        if amount <= 0:
            raise ValueError("金额必须为正")
        self._balance += amount

    def get_balance(self) -> float:
        return self._balance

acc = Account("tom", 100)
acc.deposit(50)
print(acc.get_balance())    # 150
print(acc._balance)         # 150，能访问，只是IDE会警告：约定是别这么做
# print(acc.__pin)          # AttributeError
print(acc._Account__pin)    # 1234，双下划线被改写成 _类名__属性，"防误碰"而非真私有
```

理解两点：

1. 单下划线 _x是君子协定："这是内部实现，外部请用方法访问"。Python社区九成场景用它就够了。
2. 双下划线 __x触发名称改写，主要目的其实是**避免子类意外覆盖**，不是提供安全。不要指望它保护密码——真敏感信息该哈希加密，不是靠命名约定。

## dataclass：现代Python的写法（3.7+，3.12完全成熟）

大部分类的 __init__ 只是把参数赋给同名属性，dataclass自动生成这些样板：

```python
from dataclasses import dataclass, field

@dataclass
class Point:
    x: float
    y: float = 0.0            # 有默认值def distance_to_origin(self) -> float:
        return (self.x ** 2 + self.y ** 2) ** 0.5

p = Point(3.0, 4.0)
print(p)                      # Point(x=3.0, y=4.0)，自动生成 __repr__
print(p == Point(3.0, 4.0))   # True，自动生成 __eq__

@dataclass
class Cart:
    items: list[str] = field(default_factory=list)   # 可变默认值必须用field
    total: float = 0.0

c1, c2 = Cart(), Cart()
c1.items.append("apple")
print(c1, c2)     # Cart(items=['apple'], total=0.0) Cart(items=[], total=0.0)，互不影响
```

field(default_factory=list) 是dataclass里"可变默认值"的正确写法（原理同第7篇默认参数坑：每次实例化要新建一个列表，不能共享）。

Pydantic（FastAPI的底座）是dataclass的强化版：自动类型校验。第12模块和04模块会大量接触。

## 常见坑

**方法忘写self**：报takes 0 positional arguments but 1 was given，回看第2节self的机制。

**__init__ 里漏赋值**：后面访问属性抛AttributeError。类的属性全部在 __init__ 里集中声明是团队规范。

**类属性当实例状态用**：count = [] 写在类上，所有实例往里append全混在一起。个体状态进 __init__。

**可变默认值进dataclass**：用field(default_factory=...)。

**误以为 __ 真私有**：_Account__pin照样能访问。安全靠加密和权限，不靠命名。
