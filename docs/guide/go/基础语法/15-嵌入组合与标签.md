# 嵌入、组合与标签

Go 没有继承，用"组合 + 嵌入"实现代码复用，用标签（tag）控制 JSON 序列化。这一篇讲清这两件事。

## 嵌入：字段与方法的提升

嵌入是把一个类型匿名放进另一个结构体，它的字段和方法被自动"提升"：

```go
type Base struct {
	ID        int
	CreatedAt time.Time
}

func (b Base) Info() string { return fmt.Sprintf("ID:%d", b.ID) }

type Order struct {
	Base              // 匿名嵌入：不是字段名，是"提升"
	Title string
}

o := Order{Base: Base{ID: 1}, Title: "x"}
fmt.Println(o.ID)          // 直接访问嵌入字段（提升）
o.Info()                   // 方法也提升：Order 获得 Base 的方法
```

注意嵌入不是继承：Order 和 Base 没有父子关系，不能多态替换。它只是"字段提升"的语法糖。

## 组合：依赖注入

Go 面向对象的姿势是"小接口 + 组合 + 依赖注入"：

```go
type Logger interface {
	Log(msg string)
}

type RepairService struct {
	logger Logger          // 依赖注入：谁实现 Logger 都能用
}

func (s *RepairService) Process(o *Order) {
	s.logger.Log("processing " + o.Title)
}
```

Python 篇讲过"组合优于继承"，Go 没有继承，组合是唯一选项，反而简单。

## 结构体标签：JSON 序列化的元数据

```go
type Order struct {
	ID       int      `json:"id"`
	Title    string   `json:"title"`
	Status   string   `json:"status"`
	Password string   `json:"-"`               // 序列化时忽略（防泄漏）
	Inner    string   `json:"inner,omitempty"` // 空值时省略
}

data, _ := json.Marshal(order)
var o Order
json.Unmarshal([]byte(raw), &o)
```

JSON 的三个高频点：

第一，json:"name" 重命名，解决 Go 大写导出和 JSON 小写惯例的差异。

第二，json:"-" 彻底隐藏字段，是响应防泄漏的结构级手段（对标 Python 的 response_model）。

第三，omitempty 在字段为空时省略输出，PATCH 部分更新时用。

## 常见坑

第一个坑：嵌入被误当继承，嵌入不会带来多态，需要父类行为时显式写 o.Base.Info()。

第二个坑：JSON 忘了写标签，导出字段全变成 Go 命名（Title），前端拿到的键大小写混乱。

第三个坑：含 slice、map、func 字段的结构体不能比较（编译报错），不能作为 map 键。
