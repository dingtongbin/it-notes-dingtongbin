# 单元测试基础

把代码写完还不够，要证明它是对的。Go 内置测试工具链，约定优于配置：文件名以 _test.go 结尾、用自带 testing 包、跑 go test 就出结果。这一篇讲单元测试怎么写、怎么组织，这是所有测试能力的地基。

## 约定：_test.go 文件

测试文件紧挨着被测代码放，命名是 名字_test.go：

```
calc.go
calc_test.go
```

一个文件只需确认包名匹配，测试函数以大写结尾的 Test 开头。此外测试通常与被测代码同在包里（白盒能看内部），但访问私有也往往有黑盒写法（包外）。

## 最小测试函数和 go test

```go
// calc_test.go
package calc

import "testing"

func TestAdd(t *testing.T) {
	got := Add(1, 2)
	if got != 3 {
		t.Errorf("Add(1,2) = %d, want 3", got)
	}
}
```

跑测试一条命令：

```bash
go test ./...
```

go test 会编译被测包、跑所有 Test 开头的函数，产出通过与否和每个测试的耗时。

## testing.T 的几个基础方法

| 方法 | 行为 |
|---|---|
| t.Error / t.Errorf | 记录失败但不停止当前测试 |
| t.Fatal / t.Fatalf | 记录失败并立即退出该测试 |
| t.Logf | 打印日志（只在失败时显示） |
| t.Run | 跑子测试 |

写多个失败的断言想都报出来，用 Error；出错了后面没法继续，用 Fatal。要看失败时的中间变量，用 Logf 输出到测试输出。

## 表驱动测试：一个函数测一组

要测一个函数的多个输入，复制粘贴会很难维护，习惯写法是把输入输出放在一个表里循环测：

```go
func TestAddTable(t *testing.T) {
	cases := []struct {
		name string
		a, b int
		want int
	}{
		{"正数相加", 1, 2, 3},
		{"负数相加", -1, -2, -3},
		{"零与正数", 0, 5, 5},
		{"边界大数", 1000000, 2000000, 3000000},
	}
	for _, tc := range cases {
		t.Run(tc.name, func(st *testing.T) {
			if got := Add(tc.a, tc.b); got != tc.want {
				st.Errorf("Add(%d,%d) = %d, want %d", tc.a, tc.b, got, tc.want)
			}
		})
	}
}
```

## 子测试与细分

t.Run 让每个用例成为一个子测试。好处：单独看哪个用例挂了、可以筛选只跑其中一个：

```bash
go test -run 'TestAddTable/正数相加'   # 只跑这个子测试
go test -v                             # 详细输出子测试结果
```

表驱动 + 子测试是 Go 测试最主流的形态：一张表覆盖边界和常见情况，每个用例自成子测试，定位和排查都清晰。

## 只测必要的：域要纯净

单元测试的单元最好不依赖外部：不通数据库、不发网络请求、不读文件。对依赖抽象成接口或函数注入，测试里换假实现，让测试又快又稳、不随环境波动。这个思路在专门讲测试策略时会展开。

## 小结

Go 测试的骨架很固定：_test.go + testing.T + go test。在此基础上，用表驱动覆盖多输入、用 t.Run 组织子测试、用 Error/Fatal 区分记录与退出。掌握这套，写每个函数都顺手补上测试，就守住了最基本的正确性。
