# 结构体与方法

Go 没有 class，只有结构体（struct）和方法（method）。这一篇讲定义、实例化、方法接收者、构造函数惯例，以及隐藏的可见性规则。

## 定义与实例化

```go
type Order struct {
	ID        int
	Title     string
	Status    string        // 大写：导出（包外可见）
	urgent    bool          // 小写：包内私有
	CreatedAt time.Time
}
```

三种实例化方式：

```go
o1 := Order{ID: 1, Title: "投影仪维修"}                    // 字段名初始化（推荐）
o2 := Order{1, "打印机卡纸", "pending", false, time.Now()}   // 位置初始化（易错少用）
var o3 Order                                               // 零值结构体

o4 := &Order{ID: 2}        // 指针实例化
fmt.Println(o4.ID)         // Go 自动解引用，不用 (*o4).ID
```

字段名初始化是推荐写法，抗字段增删调整。

## 方法：值接收者 vs 指针接收者

方法是带接收者的函数：

```go
func (o Order) Summary() string {          // 值接收者：拿到拷贝
	return fmt.Sprintf("#%d %s [%s]", o.ID, o.Title, o.Status)
}

func (o *Order) Pay() error {              // 指针接收者：能修改原结构体
	if o.Status != "pending" {
		return fmt.Errorf("order %d not pending", o.ID)
	}
	o.Status = "paid"                      // 修改生效
	return nil
}

o := Order{ID: 1, Status: "pending"}
fmt.Println(o.Summary())
if err := o.Pay(); err != nil {
	log.Fatal(err)
}
fmt.Println(o.Status)                      // paid
```

选择规则背下来：

第一，方法需要修改接收者就用指针接收者。

第二，结构体很大（几十个字段）用指针接收者，避免拷贝。

第三，含 map/slice 字段时用指针，避免共享层引发困惑。

第四，同一个类型的方法集要保持一致，混用是指针接口陷阱的根源，接口篇会讲。

## 构造函数：NewXxx 惯例

Go 没有构造函数，惯例是 New 前缀的函数：

```go
func NewOrder(title string, reporterID int) (*Order, error) {
	if strings.TrimSpace(title) == "" {
		return nil, errors.New("title is required")
	}
	return &Order{
		ID:        nextID(),
		Title:     title,
		Status:    "pending",
		CreatedAt: time.Now(),
	}, nil
}

o, err := NewOrder("投影仪维修", 7)
if err != nil {
	// 处理错误
}
```

价值在于把参数校验、默认值、私有字段初始化集中在一处。配合私有字段可以强制只能通过 NewXxx 创建对象，保证不变量。

## 常见坑

第一个坑：值接收者里改字段无效，改的是拷贝。要改状态必须指针接收者。

第二个坑：位置初始化加字段后全部错位，跨文件编译不报错才可怕，坚持字段名初始化。

第三个坑：函数传结构体是整体拷贝，大结构体传指针更高效且语义清晰。
