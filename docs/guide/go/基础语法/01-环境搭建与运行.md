# 环境搭建与运行

Go 的卖点是简单、并发、编译快：部署产物是单个二进制，交叉编译一条命令。这一篇解决装什么、怎么建模块、第一个程序、以及和 Python 的思维差异。

全文基于 Go 1.25。

## 安装与验证

官网下载 go 安装包即可，也可以用包管理器：

```bash
# macOS
brew install go
# Linux
tar -C /usr/local -xzf go1.25.x.linux-amd64.tar.gz
```

安装后验证：

```bash
go version          # go version go1.25.x ...
go env GOPATH       # 工作区（默认 ~/go）
go env GOPROXY      # 模块代理；国内建议设七牛：
go env -w GOPROXY=https://goproxy.cn,direct
```

模块代理很重要：国内默认源访问慢甚至超时，设成国内的 goproxy.cn 后拉依赖会快很多。

## 第一个程序

创建一个目录并初始化模块。模块名建议用域名风格，例如生产项目用 github.com/you/项目名，这里先用简单的 hello 演示。

```bash
mkdir hello && cd hello
go mod init hello
```

写入口文件的代码：

```go
// main.go
package main

import "fmt"

func main() {
	fmt.Println("Hello, Go")
}
```

运行与构建是两条不同的命令，记住区别：

```bash
go run main.go      # 编译并运行（开发时用）
go build            # 产出 hello.exe / hello 二进制（部署用）
./hello
```

和 Python 第一眼就能看到差异：必须有 package main 声明；入口必须是 main 函数（还要在 main 包里）；花括号必写且左花括号不能换行（gofmt 强制）。

Go 自带格式化与静态检查工具，团队里没有格式争议：

```bash
go fmt ./...        # 格式化
go vet ./...        # 静态检查
gofmt -l .          # 列出未格式化文件
```

## 模块机制：go.mod 与依赖

go.mod 记录模块信息和依赖，是 Go 的"项目身份证"：

```bash
go mod init github.com/you/repair-cli   # 模块名（建议域名风格）
go get github.com/google/uuid           # 添加依赖
go get github.com/google/uuid@v1.6.0    # 指定版本
go mod tidy                             # 清理：补齐用到的、删掉没用的（保存后必跑）
```

go.mod 长得像这样：

```go
// go.mod
module github.com/you/repair-cli

go 1.25

require github.com/google/uuid v1.6.0
```

配合 go.mod 还有一个 go.sum 文件，它记录每个依赖的哈希，用于完整性校验，必须进 git，对标 Python 的锁文件。

对照 Python 理解：go.mod 接近 pyproject.toml 的依赖声明，go.sum 接近锁文件，go mod tidy 接近 pip 同步。但 Go 没有虚拟环境问题：依赖按模块隔离，全局缓存（GOMODCACHE）共享下载，天生解决多项目多版本冲突。

## 程序结构：包与可见性

Go 目录里的每个文件夹是一个包。约定：目录名等于包名，全小写无下划线，按领域命名（config、ssh、terminal），不要用 utils、helpers 这种垃圾抽屉命名。

可见性规则是 Go 的特色：不用 public/private 关键字，用大小写区分。大写字母开头表示导出（包外可见），小写表示包内私有。

```go
// config.go
package config

// 大写开头 = 导出；小写 = 包内私有
type Config struct {
	Host  string
	Port  int
	debug bool // 小写：包外不可见
}

func Load() Config { // 导出函数
	return Config{Host: "127.0.0.1", Port: 22}
}
```

另一个包使用它：

```go
// main.go
package main

import (
	"fmt"

	"github.com/you/repair-cli/internal/config"
)

func main() {
	cfg := config.Load()
	fmt.Println(cfg.Host, cfg.Port)
}
```

internal 目录有个特殊地位：编译器强制它的子包只能被本模块导入，外部项目 import 会直接编译报错。这是 Go 的强制封装能力，Python、JS 都做不到。

## 交叉编译与构建

一条命令能出任意平台的单文件二进制，这是 Go 做命令行和部署工具的杀手锏：

```bash
GOOS=windows GOARCH=amd64 go build -o app.exe
GOOS=linux   GOARCH=arm64 go build -o app-linux-arm64
GOOS=darwin  GOARCH=amd64 go build -o app-mac
```

瘦身与安装：

```bash
go build -ldflags="-s -w" -o app   # 去符号表瘦身（可减 30%）
go install github.com/some/tool@latest   # 安装工具到 GOPATH/bin
```

## 与 Python 的思维差异

需要扭过来的两个最大习惯：

第一，没有异常。错误是普通返回值，if err != nil 是主旋律，后面错误处理篇会细讲。

第二，没有类继承。只有结构体组合加接口隐式实现，面向对象篇展开。

一个顶层差异表格：

| 维度 | Python | Go |
|---|---|---|
| 类型 | 动态 + 可选注解 | 静态强类型 |
| 并发 | 线程/协程受 GIL | goroutine 天生并发 |
| 错误 | 异常 try/except | 返回值 error |
| 编译 | 解释 | 编译成机器码 |
| 部署 | 解释器 + 依赖 | 单个二进制 |
| 格式 | PEP8（约定） | gofmt（强制） |

## 常见坑

第一个坑是分不清 go run 和 go build：run 临时编译到缓存，build 产出文件，部署永远 build。

第二个坑是 go.mod 里的 go 1.25 表示最低版本要求而不是你的安装版本，升级依赖后 go mod tidy 会自动调整。

第三个坑是循环导入：A 导 B、B 导 A 直接编译失败。解决办法是把两者公用的部分下沉到第三个包。

第四个坑是看了 GOPATH 时代的旧教程：2026 年的资料要看 module 模式（有 go.mod），GOPATH/src 布局已经是历史。
