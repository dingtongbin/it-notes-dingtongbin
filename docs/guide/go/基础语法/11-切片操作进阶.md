# 切片操作进阶

切片的增删、预分配、以及和 make 的配合。这一篇是高频实战操作集。

## append 与扩容

```go
s := make([]int, 0, 4)     // len=0, cap=4：预分配（知道大小时显著提速）
s = append(s, 1, 2)        // [1 2]，len=2 cap=4
s = append(s, 5)           // 超容量 -> 扩容：分配更大的新数组并拷贝
```

扩容规则大致是：小切片约 2 倍增长，超过阈值后约 1.25 倍。关键是 append 必须接收返回值，因为扩容后 s 指向新数组，不接返回值就丢了：

```go
// s = append(s, 5) 而不是独立一行 append(s, 5)
```

删除元素没有内置方法，用切片拼接：

```go
s := []int{1, 2, 3, 4, 5}
s = append(s[:2], s[3:]...)        // 删除下标 2：[1 2 4 5]
```

插入：

```go
s = append(s[:2], append([]int{99}, s[2:]...)...)   // 在下标 2 插入 99
```

## make 与 nil 切片

```go
var s1 []int                 // nil 切片：len=cap=0，可 append，可 range
fmt.Println(s1 == nil, len(s1))   // true 0
s2 := []int{}                // 空切片：len=0 cap=0，非 nil
s3 := make([]int, 3)         // 长度 3 的零值切片 [0 0 0]
s4 := make([]int, 0, 100)    // 长度 0 容量 100（预分配）
```

nil 切片和空切片在 JSON 序列化时不同：nil 变成 null，空切片变成 []，前端判空要留意。

## 二维切片

建二维切片每行必须独立分配：

```go
grid := make([][]int, 3)
for i := range grid {
	grid[i] = make([]int, 3)      // 每行独立分配
}
grid[0][0] = 1
```

## 常见坑

第一个坑：append 忘了接收返回值，扩容后数据"丢失"。

第二个坑：已经知道规模却不预分配，多次扩容反复拷贝，性能浪费。

第三个坑：JSON 序列化时 API 返回 null 导致前端 .length 报错，出参统一初始化为空切片。
