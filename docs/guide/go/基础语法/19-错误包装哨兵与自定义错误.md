# 错误包装、哨兵与自定义错误

Go 1.13 之后，错误处理有了分水岭写法：errors.Is、errors.As 穿透包装链。这一篇讲哨兵错误、自定义错误类型和选型。

## 错误包装与解包

用 %w 包装会形成错误链，错误信息逐层保留：

```go
var baseErr = errors.New("connection refused")
wrapped := fmt.Errorf("dial db: %w", baseErr)
wrapped2 := fmt.Errorf("start server: %w", wrapped)

fmt.Println(wrapped2)
// start server: dial db: connection refused
```

判断链上是否包含某错误，用 errors.Is 替代 == 比较：

```go
if errors.Is(err, baseErr) { ... }              // 沿包装链逐层找
```

从链上取出特定类型的错误，用 errors.As：

```go
type NotFoundError struct{ Key string }
func (e *NotFoundError) Error() string { return "not found: " + e.Key }

var nf *NotFoundError
if errors.As(err, &nf) {
	fmt.Println("缺失的键:", nf.Key)             // 拿到结构化字段
}
```

errors.Is 代替 err == sentinel，errors.As 代替类型断言，因为它们穿透包装链。

## 哨兵错误

预定义的"已知错误"，供调用方判断分支：

```go
// 包级定义
var (
	ErrNotFound   = errors.New("not found")
	ErrPermission = errors.New("permission denied")
)

// 库代码返回它
func Load(key string) ([]byte, error) {
	// ...
	return nil, ErrNotFound
}

// 调用方用 errors.Is 分支
_, err := Load("a")
switch {
case errors.Is(err, ErrNotFound):
	return nil                                    // 没有就算了
case errors.Is(err, ErrPermission):
	return err
default:
	return fmt.Errorf("load: %w", err)
}
```

标准库的 io.EOF、sql.ErrNoRows 都是哨兵错误。

## 自定义错误类型

需要携带结构化信息、程序化判断（重试、分类）时定义类型：

```go
type ApiError struct {
	Status  int
	Code    string
	Message string
}

func (e *ApiError) Error() string {
	return fmt.Sprintf("[%d %s] %s", e.Status, e.Code, e.Message)
}

func (e *ApiError) Retryable() bool {
	return e.Status == 429 || e.Status >= 500
}

// 使用 + errors.As 解包
resp, err := callAPI(ctx)
var apiErr *ApiError
if errors.As(err, &apiErr) && apiErr.Retryable() {
	return retry()
}
```

选型原则：一句话说得清就用 errors.New 或 fmt.Errorf；要程序化判断（重试、分类、取字段）就用自定义类型。

## 常见坑

第一个坑：用 == 比较错误在包装后失效，统一用 errors.Is、errors.As。

第二个坑：自定义错误类型要用指针接收者实现 Error，且 errors.As 匹配指针。
