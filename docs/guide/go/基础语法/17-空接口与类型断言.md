# 空接口与类型断言

空接口 interface{}（别名 any）能装任何类型，但取出时必须类型断言。这一篇讲 any 的用途、断言语法和 nil 陷阱。

## 空接口 any

没有方法的接口叫空接口，任何类型都满足它：

```go
var x any = 42
x = "hello"
x = []int{1, 2}
```

用途集中在两处：万能容器（如解析 JSON 的动态结构）和作为任意参数的接收方（fmt.Println 的参数就是 ...any）。

## 类型断言

从 any 拿出具体类型必须断言。直接断言在类型不符时会 panic，用逗号-ok 更安全：

```go
var v any = "hello"

// comma-ok 断言（安全版）
s, ok := v.(string)
if ok {
	fmt.Println(len(s))
} else {
	fmt.Println("不是 string")
}
```

## type switch

需要按类型分支时用 type switch，每个分支里变量是对应类型：

```go
func describe(v any) string {
	switch x := v.(type) {
	case nil:
		return "nil"
	case int:
		return fmt.Sprintf("int: %d", x)
	case string:
		return fmt.Sprintf("string: %s", x)
	case fmt.Stringer:                // 还能匹配接口！实现了 String() 的类型
		return "has String(): " + x.String()
	default:
		return "unknown"
	}
}
```

## nil 接口陷阱（面试名题）

接口值在内部是"类型信息 + 数据指针"二元组。一个常见 bug：

```go
type Storage interface {
	Save(key string, data []byte) error
	Load(key string) ([]byte, error)
}

func create() Storage {
	var m *MemoryStorage    // 类型 *MemoryStorage，值 nil
	return m                // 接口 = (*MemoryStorage, nil)，不是 nil 接口！
}
s2 := create()
fmt.Println(s2 == nil)              // false！！（类型信息非空）
// 但调用它的方法会 nil panic
```

工程结论：返回接口的函数，错误路径要 return nil（接口零值），而不是返回 nil 指针。

## 常见坑

第一个坑：any 滥用。类型信息全丢，只在边界处（JSON 解析、通用容器）用，业务代码用具体类型或泛型。

第二个坑：直接断言 v.(int) 在类型不符时 panic，判定存在与否用 comma-ok 版本。
