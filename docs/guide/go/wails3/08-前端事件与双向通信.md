# 前端事件与双向通信

事件通道默认方向是 Go 推给前端，但反向也存在：前端发事件给 Go。虽然大多数跨层调用用绑定方法就够了，但某些广播场景用事件更顺手。这一篇讲反向事件怎么用，以及什么时候该用哪个。

## 前端发事件给 Go

Go 侧可以订阅前端发来的事件：

```go
app.Event.On("ui:theme-changed", func(e *application.WailsEvent) {
	theme := e.Data.(string)
	log.Println("用户切换主题:", theme)
})
```

前端通过 runtime 发送：

```typescript
import { Events } from "../wailsjs/runtime";
Events.Emit("ui:theme-changed", "dark");
```

注意 e.Data 在 Go 侧是空接口，需要类型断言取回具体类型。不像绑定方法那样有强类型，用的时候要先确认自己能断言的类型。

## 该用绑定方法还是事件

这是最常纠结的问题，有一条简洁的约定：

- 数据流用绑定方法：有返回值、类型安全，前端调一次拿一个结果。
- 通知广播用事件：一对多、无返回值，适合谁都能关心的消息。

一个请求想要一个明确结果，走绑定；一件可能有很多人关心、且不用回执的事，走事件。

## 广播和定向的区别

Go 用应用级 EmitEvent 时，所有窗口都会收到。如果只想通知某个特定窗口，用窗口级 Emit 定向发送。这在多窗口场景下很重要，防止一个窗口的消息打扰所有窗口。

## 组合起来的双向模型

两条通道加上双向事件，桌面应用就有了完整的通信能力：

```
前端 ──绑定方法──▶ Go   请求/响应
Go   ──事件──────▶ 前端   推送
前端 ──事件──────▶ Go    广播通知
```

绝大多数跨层调用走第一条和第二条；第三条只用于纯广播，避免滥用。理解的检验标准是：能不能对着任意一个交互立刻说出来它该走哪条通道、为什么。
