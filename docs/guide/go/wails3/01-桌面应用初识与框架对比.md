# 桌面应用初识与框架对比

前面 Go 的基础语法教会你怎么写逻辑，web开发章节教会你用它搭 HTTP 服务。从这一章开始，把 Go 的能力带到桌面：做一个系统 WebView 渲染界面、Go 写后端、最后打包成单个可执行文件的桌面程序。这一篇先搞清楚它到底是什么、为什么存在、和 Electron 这类方案差在哪。

## 它是什么

一句话：Go 后端 + Web 前端（用系统自带的 WebView 渲染）+ 单二进制打包。前端用你熟悉的 Vue 和 TypeScript，所有计算机能力全都走 Go。

它既有 Web 前端的开发效率（Vue 生态、全量 CSS/TS 工具链、热更新），又有桌面应用的能力（调用系统 API、访问文件、原生窗口、托盘、快捷键）。

## 分层结构

```
┌────────────────────────────────┐
│  前端进程（WebView 渲染）        │  Vue + TS，只负责界面
│  按钮/输入框/列表/图表           │
└──────────┬──────────┬──────────┘
           │ 调用绑定   │ 订阅事件
           ▼          ▼
┌────────────────────────────────┐
│  Go 主进程                     │
│  Service 层 + 后台 goroutine    │  真正的逻辑都在这里
└────────────────────────────────┘
```

前端和 Go 之间是两条通道：前端主动调 Go 的方法叫绑定，Go 主动往前端推数据叫事件。这两条通道封装了底层的一切通讯细节。

## 与 Electron 的对比

Electron 是桌面开发的另一条主流路线，理解差异才能判断什么时候该用哪个。

| 对比点 | Wails | Electron |
|---|---|---|
| 后端 | Go 编译成可执行文件 | Node.js + Chromium 打包进去 |
| 前端渲染 | 系统自带 WebView（不重复打包浏览器） | 内置整个 Chromium |
| 包体 | 通常几 MB 到几十 MB | 通常 100MB 起步 |
| 内存占用 | 低 | 高（一个进程 Chrome 的成本） |
| 调用系统底层能力 | Go 标准库与生态 | Node 生态与原生模块 |
| 分发 | 单文件，无运行时依赖 | 要带 Node 和 Chromium |

最大差别在包体和运行时：Wails 复用用户系统里已经装好的 WebView，所以产物是自包含的单文件；Electron 把一整套浏览器塞进去，产物自然大一个量级。

## 它适合做什么

- 运维工具：多标签终端、可视化配置、指标看板
- 内部效率软件：公司内部用的管理台、开发辅助工具
- 需要系统能力的小工具：文件处理、网络探测、定时任务

如果产品需要深度定制浏览器行为、或者将来要上移动端 Web，Electron/纯 Web 可能更合适；如果要一个轻量、低内存、能直接调系统能力的桌面工具，它有明显优势。
