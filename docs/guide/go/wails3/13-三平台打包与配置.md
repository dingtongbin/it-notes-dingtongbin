# 三平台打包与配置

打包成安装包，是用户拿到程序的最后一步。Windows、macOS、Linux 三平台产物不同、签名要求不同、注意点也不同。这一篇讲打包配置和平台差异，把三处的安装包都打明白。

## 打包配置

打包相关的配置集中在 build/config.yml：

```yaml
# build/config.yml
project:
  name: aceshell
  version: 1.0.0

nsis:                        # Windows NSIS 安装包
  allow_change_install_dir: true
  one_click: false

appimage: true               # Linux AppImage
```

项目名、版本号、各平台的打包选项都在这里。改动配置后重新打包即可。

## 三个平台的产物

| 平台 | 产物 | 签名要求 | 注意 |
|---|---|---|---|
| Windows | exe / nsis / msix | 可选（无签名易被杀软误报） | 检查 WebView2 Runtime 是否预装 |
| macOS | .app / dmg | 强制（不签名被 Gatekeeper 拦截） | 需要公证（notarization） |
| Linux | AppImage / deb | 无 | WebKitGTK 系统依赖由用户环境决定 |

以常见工具类型为例：

```bash
# Windows：绿色版 exe + NSIS 安装器；MSIX 上架商店另走链路
wails3 task package

# macOS：.app 打包成 dmg，再签名和公证
codesign --deep --force --sign "Developer ID Application: You" aceshell.app
xcrun notarytool submit app.zip --apple-id ... --team-id ... --wait
xcrun stapler staple aceshell.app

# Linux：AppImage（chmod +x 即可运行）或 deb/rpm
```

## 各平台的注意点

Windows：有没有签名影响很大。未签名的程序更容易被杀毒软件误报，发布前往往要提前提交误报申诉。另外要处理 WebView2 Runtime：Win11 内置，Win10 可能要先装，安装包可带 bootstrapper 或启动时检测引导。

macOS：签名和公证是硬性的，不公证会被 Gatekeeper 拦下来。签名证书、公证账号都要提前申请，公证结果要 stapler 回写到应用里。

Linux：系统依赖是最麻烦的，WebKitGTK 等包装没装齐全编译都过不去。发布一般给出多个发行版（Ubuntu、Arch、Debian）的抽测结果，或用官方 docker 镜像保证构建环境一致。

## 打包注意

三平台一起维护最痛苦的是环境不一致：本地能出包，CI 出不来，多半是缺系统依赖。解决思路是用容器或官方脚本把构建环境锁死，保证可复现。
