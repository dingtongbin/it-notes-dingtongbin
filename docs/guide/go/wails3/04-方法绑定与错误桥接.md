# 方法绑定与错误桥接

绑定是前端调 Go 的基本方式，可以理解成一个强类型的远程调用（RPC）：Go 的方法经过自动生成的声明暴露给前端，前端像调普通异步函数一样调用，内部走 IPC 到 Go 进程执行。这一篇讲怎么写能被前端调用的方法，以及错误是怎么传回来的。

## 能被前端调用的方法

Go 侧只要满足几个约定，方法就自动暴露给前端：

```go
package app

type AppService struct{}

func NewAppService() *AppService { return &AppService{} }

// 导出方法 = 前端可调用：大写开头 + 公开参数/返回类型
func (s *AppService) Greet(name string) string {
	return "hello " + name
}
```

一个方法能被调用，要满足：类型导出了、方法导出了（大写开头）、参数和返回类型也是公开的。前端那边会拿到自动生成的 TypeScript 声明，直接当成异步函数用：

```typescript
import { Greet } from "../wailsjs/go/app/AppService";

async function init() {
  const msg = await Greet("tom");   // 直接调用，拿返回值
  console.log(msg);                  // hello tom
}
```

绑定代码是自动生成的，不是手写的。改了 Go 方法之后要重新跑一次构建或 dev，绑定声明才会更新，否则前端会拿到旧签名。

## 复杂结构与返回

参数和返回不限于基础类型，结构体会被序列化到 JSON 再桥接过去：

```go
type SystemInfo struct {
	OS       string `json:"os"`
	Hostname string `json:"hostname"`
	CPU      int    `json:"cpu"`
}

func (s *AppService) GetSystemInfo() (*SystemInfo, error) {
	host, err := os.Hostname()
	if err != nil {
		return nil, fmt.Errorf("get hostname: %w", err)
	}
	return &SystemInfo{OS: runtime.GOOS, Hostname: host, CPU: runtime.NumCPU()}, nil
}
```

前端侧字段名对应 JSON 标签：

```typescript
import { GetSystemInfo } from "../wailsjs/go/app/AppService";

async function init() {
  const info = await GetSystemInfo();
  console.log(info.os, info.hostname, info.cpu);
}
```

## 错误自动变成 Promise reject

Go 方法返回 error 时，框架会把 error 转成前端 Promise 的拒绝。前端用 try/catch 就能接住，不需要额外的心跳或状态码：

```typescript
try {
  const info = await GetSystemInfo();
  // 成功路径
} catch (e) {
  // Go 侧 error 就在这里
  showError(e);
}
```

这层桥接让错误处理保持一致：Go 侧返回 error，前端 catch 到，语义上等价于 return err 对 return res。

## 基本流程回顾

绑定机制 = Go 方法 + 自动生成的 TS 声明 + 前端调用 + 内部 IPC 执行：

```
Go 方法  →  生成 TS 绑定  →  前端 import 直接调  →  底层 IPC 到 Go 执行  →  结果回前端
```

上下两层各自写自己熟悉的代码，中间由框架接。理解这一点，就知道为什么桌面应用里不需要真的架 HTTP 服务——绑定通道就是请求通道。
