# 多窗口与窗口管理

桌面应用常常不止一个窗口：主窗口之外有设置窗口、关于窗口、弹窗选择器等。这一篇讲怎么创建多个窗口、窗口之间怎么分流界面、前端能怎么控制当前窗口。

## 创建多个窗口

每个窗口都是一个独立的 WebviewWindow：

```go
mainWin := app.NewWebviewWindowWithOptions(application.WebviewWindowOptions{
	Title: "AceShell",
})

settingsWin := app.NewWebviewWindowWithOptions(application.WebviewWindowOptions{
	Title:       "设置",
	Width:       640,
	Height:      480,
	URL:         "/#/settings",     // 同一个前端应用的不同路由
	HideOnClose: true,              // 关闭即隐藏，可复用
})
```

注意 URL 字段：多个窗口可以指向同一个前端应用里的不同路由。主窗口走正常布局，设置窗口走 /settings 页面，用的还是同一份前端代码。

## 按启动窗口分流

前端根据自己初始化时的路由决定渲染哪个页面：

```typescript
const route = useRoute();
// 设置窗口路由到 /settings 页面，主窗口走正常布局
```

这样只要在创建窗口时指定不同 URL，同一个前端工程就能服务不同窗口，不用复制界面代码。

## 关闭即隐藏而非退出

HideOnClose 是桌面工具常见的交互：点关闭不是真正退出，而是把窗口藏起来，下次再打开复用。对常驻后台的应用（比如运维终端、托盘工具）尤其顺手。代价是用户可能以为退出了，实际还在占资源，所以一般配合托盘和明确的提示。

## 前端控制当前窗口

窗口的控制能力通过绑定方法暴露给前端：

```go
func (s *WindowService) ToggleFullscreen() {
	win := app.CurrentWindow()
	win.SetFullscreen(!win.Fullscreen())
}
```

前端能触发的窗口操作：全屏切换、最小化、隐藏、置顶等。把这些也包成服务绑定方法，前端就能在界面上提供按钮控制窗口行为。

## 对话框与文件选择

系统级能力（比如文件选择框）只有主进程有，也通过绑定暴露：

```go
func (s *AppService) PickLogFile() (string, error) {
	win := app.CurrentWindow()
	result, err := win.OpenFileDialog(application.OpenFileDialogOptions{
		Title: "选择日志文件",
		Filters: []application.FileFilter{
			{ DisplayName: "日志", Pattern: "*.log;*.txt" },
		},
	})
	return result, err
}
```

前端调用 PickLogFile，拿到用户选择的路径，全程走绑定通道，文件系统访问留在 Go 侧。

## 常见坑

1. 多窗口事件互相干扰：广播事件所有窗口都收到，需要定向时用窗口级 Emit。
2. 关闭即退出的预期差：HideOnClose 后后台还在占资源，要有托盘和明确提示。
3. 文件选择等系统能力：只能从 Go 侧调，必须包成绑定方法。
