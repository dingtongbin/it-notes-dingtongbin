# CI 自动构建与发布

手动在本地逐个平台打包既慢又不可复现。把构建放进 CI，推到 GitHub 打一个 tag 就能自动出三平台安装包并挂到 Release 页。这一篇以 GitHub Actions 为例讲这套流水线怎么搭。

## 一个典型的三平台流水线

打 tag 触发，三个平台各跑一个构建，最后汇总发布：

```yaml
# .github/workflows/release.yml
name: release
on:
  push:
    tags: ["v*"]

jobs:
  build:
    strategy:
      matrix:
        include:
          - { os: windows-latest, platform: windows/amd64 }
          - { os: macos-latest,   platform: darwin/universal }
          - { os: ubuntu-22.04,   platform: linux/amd64 }
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version: "1.25" }
      - uses: actions/setup-node@v4
        with: { node-version: "20" }

      - name: Install Linux deps
        if: runner.os == 'Linux'
        run: sudo apt-get update && sudo apt-get install -y libgtk-3-dev libwebkit2gtk-4.1-dev

      - name: Build
        run: |
          cd frontend && npm ci && npm run build && cd ..
          wails3 task build -platform ${{ matrix.platform }}

      - name: Upload artifacts
        uses: actions/upload-artifact@v4
        with:
          name: aceshell-${{ matrix.platform }}
          path: build/bin/*

  release:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/download-artifact@v4
      - uses: softprops/action-gh-release@v2
        with:
          files: "**/*"
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

## 拆开看关键点

matrix 让同一个 job 在三套系统上跑三次，每套系统有自己对应的 platform 参数。Linux 的 job 额外装系统依赖，因为 WebKitGTK 在构建机上不会自带。

每个平台构建产物通过 upload-artifact 上传，最后一个 release job 等在它们之后，下载所有产物，用 softprops/action-gh-release 挂到 Release。runs-on 加 needs 保证发布在所有平台都构建成功之后才执行，防止部分平台失败还发布半成品。

## 版本注入放在 CI

版本号不该在本地靠记忆统一，而是由 CI 配合 tag 注入。tag 就是版本号来源，二进制里的版本信息从 tag 派生，再用 ldflags 注入，从源头保证版本号一致，避免 code 里是 dev、tag 是 v1.2.0 的漂移。

## 落地步骤

1. 本地起一次构建，确认环境依赖都清楚了。
2. 把流水线文件提交到仓库。
3. 本地打一个 v0.1.0 的 tag 推送，观察 Action 跑通。
4. 首次可以先只出 artifact 不出 Release，确认产物无误再放开发布。

## 常见坑

1. release 假设了构建机环境：本地能编 CI 不行，多是缺系统依赖，用容器或脚本锁死环境。
2. 三个平台相互等待：只要有一个失败 release 就停，先单独验证每个平台。
3. 产物路径不一致：不同平台输出路径可能不同，upload 的 path 要按平台处理。
