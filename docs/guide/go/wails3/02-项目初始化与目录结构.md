# 项目初始化与目录结构

环境搭好、前一篇看完框架定位，这一篇把工程建起来，搞清楚每个目录是干什么的，再跑通开发命令。读完后你会有一个能改能跑的 Wails3 项目骨架。

## 初始化项目

先安装命令行工具，然后用它生成一个 Vue + TypeScript 模板项目：

```bash
go install github.com/wailsapp/wails/v3/cmd/wails3@latest

wails3 init -n aceshell -t vue-ts
cd aceshell
wails3 task dev
```

最后一条 dev 是开发模式：前端有热更新，Go 侧改动会触发重新编译，两个进程协作，改完基本能即时看到效果。

## 目录结构

初始化出的工程长这样：

```
aceshell/
├── main.go                # 应用入口
├── app/                   # Go 服务层（绑定的方法在这）
│   └── app.go
├── frontend/              # Vue 项目（普通 Vite 工程）
│   ├── src/
│   └── package.json
├── build/                 # 打包资源（图标/配置）
├── Taskfile.yml           # 任务脚本（wails3 task ...）
└── go.mod
```

几个关键点：

- main.go 是唯一入口，应用装配都发生在这里。
- app/ 放的是要绑定给前端的 Go 方法，是前后端之间的桥。
- frontend/ 就是一个标准的 Vite + Vue 工程，可以完全按 Web 前端的方式开发。
- build/ 里是打包用的资源，比如程序图标和平台相关的打包配置。
- Taskfile.yml 定义了各种 task，dev、build、doctor 这些命令都由它驱动。

## 常用开发命令

| 命令 | 作用 |
|---|---|
| wails3 task dev | 开发模式，前端 HMR + Go 热编译 |
| wails3 task build | 构建当前平台的可执行文件 |
| wails3 task doctor | 环境自检，检查 WebView 等系统依赖是否齐全 |
| wails3 task package:<平台> | 打出安装包（不同平台不同） |

## 前端部分就是标准 Vite

界面层不需要学新东西，它就是平时写的 Vue：

```bash
cd frontend && npm run build
```

前端构建产物会被打进 Go 二进制，这在下一篇讲入口时展开。开发阶段用 dev 跑起来即可，前端和后端共享同一套热更新体验。

## WebView 依赖

程序靠系统自带的 WebView 渲染界面，不同平台依赖不同：

| 平台 | WebView | 需要注意 |
|---|---|---|
| Windows | WebView2 Runtime | Win11 内置，Win10 可能要先装 |
| macOS | WKWebView | 系统自带，无额外依赖 |
| Linux | WebKitGTK | 需要装系统包，依赖最多 |

Linux 上依赖最多，装不全连编译都过不去。不确定缺什么就先跑 wails3 task doctor，它会把缺的系统依赖明确列出来。
