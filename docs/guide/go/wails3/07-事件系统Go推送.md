# 事件系统：Go 推数据给前端

绑定是前端发起、Go 响应。还有反方向的一种通信：Go 主动把数据推给前端。日志流、传输进度、会话状态变化这类"实时变化"都靠它。这一篇讲事件系统怎么用。

## Go 侧发事件

事件既可以发给单个窗口，也可以应用级广播：

```go
import "github.com/wailsapp/wails/v3/pkg/application"

// 指定窗口发事件
func (s *TerminalService) emitProgress(win *application.WebviewWindow, id string, pct int) {
	win.EmitEvent("sftp:progress", map[string]any{
		"id":    id,
		"pct":   pct,
		"speed": "2.4MB/s",
	})
}

// 应用级广播：所有窗口都能收到
app.EmitEvent("log:new", map[string]any{
	"level": "ERROR",
	"msg":   "connection lost",
})
```

事件名用冒号分层，前缀带领域，比如 sftp:、terminal:、log:，既避免重名也方便归类。payload 是任意结构，通常会序列化成 JSON 到前端。

## 前端订阅事件

前端用 Events.On 订阅，订阅函数返回一个取消函数，组件卸载时要退订：

```typescript
import { Events } from "../wailsjs/runtime";

Events.On("sftp:progress", (data: { id: string; pct: number }) => {
  updateProgress(data.id, data.pct);   // UI 实时刷新
});

// 取消订阅（卸载时防泄漏）
const off = Events.On("log:new", handler);
onUnmounted(() => off());
```

订阅事件的第二个参数来自 payload 的类型，前端一般自己声明 interface 做强类型提示。

## 和 Web 世界的对照

如果熟悉 Web，事件和绑定正好对应两种通道：

| 通道 | 方向 | 类比 Web |
|---|---|---|
| 绑定方法 | 前端 → Go | HTTP 请求（有返回值） |
| 事件 | Go → 前端 | WebSocket 推送（主动通知） |

所以桌面应用里不需要真的架 HTTP/WebSocket 服务：绑定覆盖请求，事件覆盖推送，两条通道就够了。

## 典型数据流

以文件传输为例，看看两条通道怎么配合：

```
前端：调 SftpUpload(sessionID, localPath, remotePath)   [绑定方法]
Go：  起后台 goroutine 传输，每秒 EmitEvent("sftp:progress", {...})
前端：Events.On 更新进度条；完成时收到 sftp:done
```

前端的动作走绑定，进度的实时变化走事件，正在上传中的新信息自动就推过来了。

## 高频事件的节制

如果每处理一个字节就发一个事件，前端会被刷屏、UI 卡住。做法是节流：Go 侧用 time.Ticker 定时汇报，比如每 200 毫秒发一次进度的相对偏移/百分比，或者只发关键节点的偏移量，由前端自己算进度。
