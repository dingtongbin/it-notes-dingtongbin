# 容器资源限制

不限制资源，一个失控的容器可能吃光整台机器，把邻居都拖垮。这一篇讲 Docker 怎么给容器设 CPU 和内存上限，这些限制在 K8s 里同样适用。

## 限制内存

内存超了是最危险的，可能触发容器被系统 OOM 杀。所以内存既要有软性的尽量，也要有硬性的上限：

```bash
# 最多 512M，超了杀进程（-m 是硬上限）
docker run -d -m 512m myapp

# 更安全的组合：预留 + 上限
docker run -d --memory-reservation 256m -m 512m myapp
```

-m 是容器绝不允许超过的内存；--memory-reservation 是期望值，资源充裕时也能多用。内存超过硬上限时，docker 会把进程 OOM 杀掉。

## 限制 CPU

CPU 用相对份额和硬上限两种：

```bash
# 相对权重：默认 1024，数值越大分到的 CPU 越多
docker run -d --cpu-shares 2048 myapp

# 硬上限：限定只能用 1.5 个核
docker run -d --cpus 1.5 myapp
```

--cpus 1.5 表示最多用 1.5 个 CPU 核，是更直观的硬限制。--cpu-shares 是软性份额，只在 CPU 争抢时才起作用。

## 查看限制是否生效

```bash
docker stats          # 实时看每个容器的 CPU 和内存占用
docker inspect <容器>  # 看配置里的限制项
```

docker stats 是最常用的排查工具，能一眼看出哪个容器在吃内存。

## 底层就是 cgroup

这些限制落到 Linux 就是 cgroup v2 的内存和 CPU 控制组。一个容器对应一组 cgroup 配置，内核在调度时按这组配置执行限额。所以限制是内核强制的，不是 Docker 做做样子的。

## 限制组合怎么用

| 目标 | 命令 |
|---|---|
| 只限制内存 | -m 512m |
| 明确 CPU 核 | --cpus 1.5 |
| 限制 CPU + 内存 | 两个一起加 |

生产里通常都会给 CPU 和内存都设一个合理的上限，避免单个服务脱缰拖垮宿主机上的其他容器。

## 小结

限制的本质是给每个容器划一条资源的红线。理解这一点，再去看 K8s 里的 limits 和 requests，会发现是同一套思想：requests 是保证，limits 是上限。
