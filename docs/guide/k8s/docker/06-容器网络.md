# 容器网络

容器之间、容器与宿主怎么通信，是 Docker 里最容易困惑的部分。这一篇讲 Docker 的几种网络模式、端口映射到底做了什么，以及容器如何互相访问。这是理解后面 K8s 网络模型的重要一步。

## 端口映射的本质

默认每个容器只在它自己的网络命名空间里，有独立的 IP。要让外部访问容器里的服务，需要做端口映射：

```bash
docker run -d -p 8080:80 nginx
```

-p 8080:80 的意思是把宿主机的 8080 端口流量转发到容器的 80 端口。本质是宿主机上开一个转发，DNAT 到容器 IP。

## Docker 的几种网络

| 网络模型 | 特点 |
|---|---|
| bridge（默认） | 每个容器有自己的 IP，通过虚拟网桥互相通信，外部要 -p 映射 |
| host | 容器直接用宿主机网卡，没有独立 IP，性能好但隔离弱 |
| none | 容器没有网络，适合安全/隔离场景 |
| 自定义 bridge 网络 | 容器之间能通过名字互相访问，推荐做法 |

## 容器之间通信

同一个自定义 bridge 网络里的容器，可以靠容器名互相访问，不用猜 IP：

```bash
docker network create mynet
docker run -d --network mynet --name api myapp
docker run -d --network mynet --name db mysql
# 在 api 容器里可以直接 ping db 或连 db:3306
```

Docker 内置 DNS 把容器名解析成对应 IP。用自定义网络而不是默认 bridge，容器间的服务发现才有效。

## 查看与排查网络

| 命令 | 作用 |
|---|---|
| docker network ls | 列出网络 |
| docker network inspect <name> | 看网络详情和成员 |
| docker exec <容器> ip addr | 进容器看自己的 IP |
| docker port <容器> | 看映射关系 |

## 常见坑

1. 默认 bridge 里容器间不能靠名字访问：需要自定义网络或用不推荐的方式。
2. 忘映射端口外部访问不到：内部容器有 IP，但外部流量进不来，必须 -p。
3. 端口冲突：两个容器映射到宿主同一个端口会冲突，换端口。
4. host 网络下 -p 无效：host 模式直接用宿主端口，别再加映射。

## 转发链路

```
外部请求 → 宿主:8080 → 端口转发 → 容器IP:80 → 应用进程
```

理解这条链路，排查"外部访问不到"就有一条主线可循。
