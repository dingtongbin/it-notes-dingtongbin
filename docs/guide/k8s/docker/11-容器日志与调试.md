# 容器日志与调试

容器跑起来后第二件事是看它怎么了。这一篇讲怎么收集和查看容器日志，怎么进入容器排查问题，以及一些高频的调试手段。

## 日志：看容器在说什么

```bash
docker logs web                # 看所有日志
docker logs -f web             # 跟日志，实时滚动
docker logs --tail 100 web     # 只看末尾 100 行
docker logs --since 5m web     # 只看最近 5 分钟
```

容器日志会打到 stdout/stderr，docker logs 读取这两个输出。所以应用只要把日志打到标准输出，就天然被 Docker 收集。

## 进入容器调试

```bash
docker exec -it web bash       # 进入容器开 shell
docker exec web env            # 在容器里执行单条命令
docker top web                 # 看容器里的进程
```

如果镜像精简到没有 bash，就用 sh。进容器后可以看进程、环境变量、网络配置、挂载情况。

## 排查镜像内部

不用起容器也能看镜像：

```bash
docker run --rm --entrypoint env image:tag   # 覆盖入口，直接跑 env
docker run --rm -it image:tag sh             # 以 shell 方式启动临时容器
```

--rm 用完即清理，-it 交互终端。

## 进程与资源视角

```bash
docker stats                 # 容器资源占用实时表
docker inspect web           # 查看容器的完整配置和状态
```

docker inspect 能读 IP、网络、挂载、环境变量、健康状况等几乎所有信息，是调试时的高频命令。

## 日志的持久与转发

说过容器日志打到 stdout。生产里日志通常要转发到外部，比如采集进日志系统。Docker 支持配置日志驱动，把日志输出到文件、syslog 或 JSON 文件。在 K8s 里，日志采集组件会读取每个容器的日志，这跟 docker logs 是同一条路子。

## 常见坑

1. 应用把日志写到文件而不是 stdout：docker logs 就什么都看不到，日志也要走 stdout。
2. 容器起不来：看 docker logs 比干瞪眼有效，一般日志里就有原因（坏了啥、缺配置）。
3. 用 --rm 清了重要数据：临时排查容器别挂卷数据也要小心。
4. entrypoint 覆盖不掉主进程：有时要 --entrypoint 才进得去。

## 调试主线

```
容器起不来 → docker logs（找报错）
进去看环境 → docker exec -it <容器> sh
看配置状态 → docker inspect <容器> / docker stats
```

沿着这条主线，绝大多数"怎么不对"都能定位。
