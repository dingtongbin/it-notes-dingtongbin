# 流量管理：VirtualService 与 DestinationRule

网格装上后，最核心的能力是流量管理：按版本分流、灰度发布、超时重试、故障注入。这一切的入口是两个 CRD：VirtualService 描述"流量怎么走"，DestinationRule 描述"落到每个子集时的策略"。这一篇讲它们怎么配合。

## 两个角色的分工

| 资源 | 负责 |
|---|---|
| VirtualService | 从哪里来、往哪里转发、怎么切分流量 |
| DestinationRule | 转发到目标后，怎么处理（子集、超时、重试、熔断） |

两者通常配对使用：VirtualService 说"20% 流量给新版本"，DestinationRule 定义这个"新版本"是哪个子集。

## 定义一个带版本的子集

先用 DestinationRule 把 Pod 按版本分成子集：

```yaml
apiVersion: networking.istio.io/v1beta1
kind: DestinationRule
metadata:
  name: reviews
spec:
  host: reviews
  subsets:
    - name: v1
      labels:
        version: v1
    - name: v2
      labels:
        version: v2
```

子集按 Pod 的标签划分，这里把 reviews 服务的 Pod 分成 v1、v2 两拨。

## VirtualService 做流量切分

然后让 VirtualService 把流量按比例分给不同子集，实现灰度：

```yaml
apiVersion: networking.istio.io/v1beta1
kind: VirtualService
metadata:
  name: reviews
spec:
  hosts:
    - reviews
  http:
    - route:
        - destination:
            host: reviews
            subset: v1
          weight: 80          # 80% 到 v1
        - destination:
            host: reviews
            subset: v2
          weight: 20          # 20% 到 v2
```

这就是"金丝雀发布"的落地：先放 5% 到新版本，看起来没问题再慢慢调大到全量。改权重只是改配置，业务不动。

## HTTP 路由规则：按条件走

除了按权重，还能按请求条件路由：

```yaml
spec:
  hosts:
    - reviews
  http:
    - match:
        - headers:
            end-user:
              exact: jason        # 只对该用户
      route:
        - destination:
            host: reviews
            subset: v2
    - route:
        - destination:
            host: reviews
            subset: v1            # 其余全走 v1
```

按 header、URI 前缀、方法等匹配，把特定流量引到特定版本，常用于内测或预研。

## DestinationRule 的韧性策略

DestinationRule 还能给目标子集设超时、重试、连接池、熔断：

```yaml
spec:
  host: reviews
  trafficPolicy:
    connectionPool:
      tcp:
        maxConnections: 100
    outlierDetection:
      consecutive5xxErrors: 5
      interval: 10s
```

比如连续 5 次 5xx 就把该实例摘出去（熔断），隔一阵再试，防止请求堆积到一个挂掉的实例上。

## 常见坑

1. DestinationRule 和 VirtualService 引用的子集名对不上：分流失效。
2. host 写错或命名空间忘了：规则的 host 要和 Service 对齐。
3. 只改一个没改另一个：切分和策略要配套。

## 小结

VirtualService 管"流量往哪走、怎么切"，DestinationRule 管"到了以后怎么治理"。二者配合，灰度、分流、超时、重试、熔断这些能力，都用声明配置实现，业务代码完全不管。
