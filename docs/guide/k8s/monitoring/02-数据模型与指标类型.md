# 数据模型与指标类型

要看懂监控图，先看懂 Prometheus 存的是什么。这一篇讲时间序列的结构、标签、以及四类核心指标类型。数据模型是所有查询和告警的底层语言。

## 时间序列是什么

Prometheus 存的是时间序列：同一个指标在时间轴上的一系列带时间戳的值。每个时间序列由指标名 + 标签唯一确定。

```
http_requests_total{method="GET",handler="/api/users"}

一串采样点（每个值带一个时间戳）：
  10:00:00  100
  10:00:15  120
  10:00:30  135
```

## 指标名与标签

- 指标名：describe 它是什么，比如 http_requests_total、cpu_usage。
- 标签：给指标加维度，用法 name=value 的形式，一对标签由多个维度组合成一个时间序列。

```
# 同一个指标，不同 method 是两个不同的时间序列
http_requests_total{method="GET"}
http_requests_total{method="POST"}
```

标签太杂会让序列爆炸，标签太少又无法区分维度。设计标签是监控里最需要权衡的部分。

## 四类指标类型

| 类型 | 语义 | 示例 |
|---|---|---|
| Counter 计数器 | 只增不减，累加 | 请求总数、错误总数 |
| Gauge 仪表 | 可上下波动 | CPU 用率、内存、温度 |
| Histogram 直方图 | 分布统计 | 请求时延分布、直方图桶 |
| Summary 摘要 | 客户端算的分位数 | P50/P99 时延 |

### Counter

只增不减的累计量，比如总请求数。要它变成"每秒多少"，用 rate 函数对相邻点做差。这是最常见的指标，也最常用率来展示。

### Gauge

随时可上可下，只看当前值。CPU、内存、QPS 瞬时值、在线人数这类。

### Histogram 和 Summary

两者都拿来描述分布，但实现位置不同：Histogram 由 Prometheus 在服务器端聚合桶计数，Summary 由客户端算好分位数上报。Histogram 更灵活，能多做聚合，是追踪时延分布的推荐方式。

## 采样与保留

Prometheus 按抓取周期（默认 15s）采点，数据保留默认较长周期，规则可以在保留期内配合查询。理解和控制采样周期和保留期，是在存储和精度之间找平衡。

## 一个直观类比

| 概念 | 类比 |
|---|---|
| 指标名 | 表格的名字 |
| 标签 | 这张表的列 |
| 时间序列 | 一行记录 |
| 采样点 | 一行里随时间变化的值 |

## 小结

时间序列 = 指标名 + 标签 + 随时间变化的采样点。四类指标类型里 Counter 用 rate 变速率、Gauge 看现值、Histogram/Summary 表现分布。这是后面写 PromQL 和配告警的基础。
