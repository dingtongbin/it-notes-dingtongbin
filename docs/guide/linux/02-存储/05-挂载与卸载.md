# 挂载与卸载

文件系统格式化好后还无法直接使用——你需要把它"挂载"到一个目录，从此这个目录里的读写就会落到磁盘上。这篇文档解决 mount 与 umount 的完整用法、常用挂载参数，以及生产上如何规划挂载点才不坑。

## 什么是挂载

挂载（mount）的含义是把一个文件系统接到目录树中的某个位置。这个位置叫挂载点（mountpoint）。挂载后，挂载点目录里的一切读写都会被内核转交给该文件系统对应的设备。

因此挂载点的目录本身必须存在。一条原则是：不要挂载到系统根目录或正在繁忙写入的目录上，否则挂载会掩盖下面的数据。挂载点的原内容在挂载期间会被隐藏，卸载后恢复，所以别往挂载点里塞重要文件。

## 基本挂载

```bash
# 查看当前所有挂载
mount
```

```bash
# 用设备名挂载
sudo mount /dev/sdb1 /mnt/data
```

改成更稳的 UUID 引用，避免设备名因重启漂移：

```bash
sudo blkid /dev/sdb1
```

```bash
sudo mount UUID=xxxxxxxx /mnt/data
```

挂载点先创建好再挂：

```bash
sudo mkdir -p /mnt/data
sudo mount UUID=xxxxxxxx /mnt/data
```

## 常用挂载参数

挂载时可以通过 -o 传入参数。参数按需选择，不要不加思考地堆叠。

| 参数 | 作用 | 适用场景 |
| --- | --- | --- |
| defaults | 默认集合（rw、suid、dev、exec、auto、async） | 绝大多数情况 |
| ro | 只读挂载 | 备份、审查、防止误写 |
| rw | 读写挂载（默认） | 正常业务 |
| noatime | 不更新访问时间 | 减少写入、SSD 友好 |
| nosuid、nodev、noexec | 加固挂载 | 外来数据、可写目录 |
| sync / async | 同步/异步写 | 高可靠性 vs 性能取舍 |

生产上非常常见的几个组合。只读巡检：

```bash
sudo mount -o ro /dev/sdb1 /mnt/archive
```

访问时间不更新、降低写放大：

```bash
sudo mount -o noatime /dev/sdb1 /mnt/data
```

加固不可信目录：

```bash
sudo mount -o noexec,nosuid,nodev /dev/sdb1 /tmp/shared
```

## 卸载与忙碌状态处理

```bash
sudo umount /mnt/data
```

卸载失败最常见的原因是目录仍被进程占用（包括当前 shell 的工作目录）。用 fuser 或 lsof 找出占用者：

```bash
fuser -mv /mnt/data
```

```bash
sudo lsof +f -- /mnt/data
```

确认没有占用后再 umount。强制卸载是下策：

```bash
sudo umount -l /mnt/data
```

-l 表示 lazy（延迟）卸载，会等占用解除后真正断开，一般在实在无法正常卸载时才用。

## 挂载点规划

挂载点的规划直接影响目录布局，文档时把它当成和业务目录同等重要。一般的生产原则：

- 数据与系统分离：/home、数据目录、日志目录独立挂载，避免一个分区写满拖垮系统。
- 临时数据不超过挂载点：临时目录（如 /tmp）设为独立分区，避免垃圾填满根。
- 不把根目录 / 做成共享可写点：高安全环境可用 ro 挂 /，把可写路径区随需求挂起来。
- 挂载点命名用含义清楚、不含空格与特殊符号的路径，便于脚本引用。

如果只是临时看看数据，也可以事后只读卸载掉，保持全局结构干净。

## 挂载后的验证

```bash
df -h /mnt/data
```

```bash
ls -la /mnt/data
```

用 df -h 确认容量对得上，用 ls -la 确认能在挂载点看到文件系统的根内容（比如 lost+found 或新建的空文件）。

## 小结

挂载用 mount 把文件系统接到一个已存在的目录，卸载用 umount，最好用 UUID 而不是设备名来避免漂移。常用 -o 参数里 ro、noatime、noexec/nosuid/nodev 都是生产偏爱的防护与性能选项。挂载点规划要避免系统与数据混装，卸载前用 fuser/lsof 排查占用。挂载是临时行为，重启后失效，要做到开机自动挂载，需要进入下一章 fstab 的范畴。
