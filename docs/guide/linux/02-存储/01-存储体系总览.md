# 存储体系总览

这篇文档解决初学者最常见的困惑：Linux 里的"存储"到底分成哪几层？为什么同样的数据既可以说在 /dev/sda 上，又可以说在 /mnt/data 下？先建立起块设备、文件系统、对象存储的宏观框架，再认识设备命名的规律，最后上手 lsblk 一眼看清整台机器的存储拓扑。

## 存储的三层体系

生产运维里谈存储，几乎跑的都是下面三个层次：

| 层次 | 代表物 | 粒度 | 典型场景 |
| --- | --- | --- | --- |
| 块设备 | /dev/sda、/dev/nvme0n1 | 原始字节块 | 物理磁盘、RAID、云盘挂载 |
| 文件系统 | ext4、xfs、btrfs | 文件与目录 | 应用的数据目录、日志目录 |
| 对象存储 | S3、MinIO、OSS | 对象（键值+元数据） | 备份归档、静态资源、大数据 |

理解这张表的关键是分清粒度。块设备只关心"一段字节"，没有目录、没有权限，一切由驱动程序管理；文件系统建立在块设备之上，负责把字节组织成有名字、有权限、有层次的文件；对象存储则使用 HTTP 接口，打开一个 URL 就能读写一个"对象"，天然适合跨机器、跨地域访问。

## 块设备命名规则

命名规则看似随意，实际上规律很强，猜到名字就能猜到物理位置。

| 前缀 | 含义 | 举例 |
| --- | --- | --- |
| sd 开头 | SCSI、SATA、USB 盘 | sda、sdb、sdc |
| nvme0n1 | NVMe SSD | nvme0n1、nvme1n2 |
| vd | 虚拟盘（KVM/QEMU） | vda、vdb |
| xvd | 半虚拟化盘（Xen/AWS 传统） | xvda |

scsi 这类名字的后缀也有规律：同一个磁盘的第几个分区则是 sda1、sda2，前面的字母表示第几块盘（a 是第一块、b 第二块）。NVMe 的名字则类似 nvme0n1，其中中间的 0 是控制器编号，末尾的 1 是命名空间，分区则是 nvme0n1p1。

生产上用 NVMe 和 SCSI 给设备命名时，务必记住磁盘名不是物理顺序的可靠保证，重启后机器可能因为扫描顺序不同而交换名字，因此关键路径一律用文件系统 UUID 引用，这在自动挂载里尤其重要。

## 用 lsblk 一眼看拓扑

lsblk（list block devices）是排查存储问题用的第一个命令，它把设备间的树状从属关系（比如云盘里套了分区、分区里套了 LVM）画得清清楚楚。

```bash
lsblk
```

输出的树结构里，左侧是设备名，右侧 SIZE、TYPE、MOUNTPOINT 三项最有用。TYPE 是 disk、part、lvm 之类的标识，MOUNTPOINT 是当前挂在哪个目录。

只看物理盘和挂载点，加 -f 可以带上文件系统和 UUID：

```bash
lsblk -f
```

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,LABEL,MOUNTPOINT
```

其中 FSTYPE 一列最值钱，它直接告诉你某个分区是 ext4、xfs、swap 还是空白的（为空表示还没有文件系统）。只要某一块盘挂载后比预期少了空间，或者某分区格式不对，先 lsblk -f 一眼定位。

想滚动查看所有字段（含磁盘型号、序列号、厂商），可以这样指定列：

```bash
lsblk -o NAME,MODEL,SERIAL,SIZE,TYPE
```

还可以指定只看某个设备：

```bash
lsblk /dev/sdb
```

## 文件系统与对象存储的分工

在应用层眼里，文件系统和对象存储解决的是两类问题。

文件系统看重的是 POSIX 语义：重命名原子、软硬链接、块级随机读写、树状目录。数据库的 WAL、日志类的追加写、编译产物的海量小文件，都适合本地文件系统。

对象存储看重的是可扩展性：无限扩容、跨地域冗余、版本管理和生命周期策略都内置在服务里。备份镜像、缩略图、日志归档这类"写一次、读频繁、很少改"的数据，更适合对象存储。

一个常见的生产误区是拿文件系统当对象存储穷追猛打——临时用 rsync 或 cp 在分钟内能解决的问题，没必要先部署一套对象存储；反过来，需要跨机房同步的海量冷数据，放本地盘再自己搞多副本，成本和心力都远高于直接用对象存储。

## 一行命令判断空间与 inode

日常巡检基本靠两个命令，分别对应"磁盘空间"和"文件个数"两个耗尽维度：

```bash
df -h
```

```bash
df -i
```

df -h 显示容量百分比，df -i 显示 inode 使用率。很多"还有空间却写不进文件"的诡异故障，最后都查到是 inode 被小文件撑爆了。

## 小结

存储的宏观出口是先分层再排查：块设备管字节、文件系统管文件、对象存储管对象。设备命名 sd 系、nvme 系、vd 系各有规律，lsblk -f 能一站式看清拓扑、文件系统和挂载点。日常巡检用 df -h 管空间、df -i 管 inode，遇到异常先 lsblk 定位物理层，再逐层向上排查。
