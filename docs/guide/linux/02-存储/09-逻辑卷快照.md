# 逻辑卷快照

快照（Snapshot）是 LVM 的杀手级功能：给正在运行的逻辑卷拍一张"照片"，之后无论源卷怎么变，都能从照片里读出拍照时刻的数据。备份、测试破坏性操作前，都靠它兜底。

## 快照的原理

快照并不是完整复制一份数据，而是 COW（Copy-On-Write，写时复制）：

- 拍快照瞬间只记录元数据，几乎不占空间、瞬间完成。
- 之后源卷的旧块将要被改写时，先把旧块复制到快照卷保存。
- 读快照卷时：没改过的块直接读源卷，改过的块读保存的旧副本。

所以快照卷只需要存"被改过的旧数据"，体积远小于源卷。

## 创建快照

```bash
sudo lvcreate -L 10G -s -n datalv_snap /dev/datavg/datalv
```

- -s 表示快照。
- -L 10G 是快照卷的 COW 空间大小。
- -n datalv_snap 是快照名。

COW 空间多大合适？取决于快照存活期间源卷会改写多少数据。数据库这类写入频繁的场景建议给源卷大小的 10% 到 30%，只做几分钟备份窗口的话 5% 通常够。

## 查看快照状态

```bash
sudo lvs
```

关注 Data% 列：快照卷的 COW 空间用了多少。到 100% 时快照失效（源卷再改写无处保存旧块），快照变不可用。所以快照是短命工具，用完尽快删。

## 挂载与使用快照

快照卷可以像普通 LV 一样挂载，读到的就是拍照时刻的数据：

```bash
sudo mkdir -p /mnt/snap
sudo mount /dev/datavg/datalv_snap /mnt/snap
ls /mnt/snap
```

典型用途一：一致性备份。先拍快照，从快照卷备份数据（rsync/tar），源卷继续跑业务，备份完成后删除快照。这样备份期间业务的写入不影响备份一致性。

典型用途二：危险操作前兜底。升级数据库、跑批量脚本前拍快照，搞砸了从快照恢复。

## 回滚到快照

放弃快照之后的所有变更，把源卷回滚到拍照时刻：

```bash
sudo umount /mnt/data
sudo lvconvert --merge /dev/datavg/datalv_snap
```

merge 后下次激活 LV 时（或重启）执行回滚，源卷数据回到快照时刻。注意：merge 后快照卷消失，快照之后的新写入全部丢失，操作前想清楚。

## 删除快照

```bash
sudo umount /mnt/snap
sudo lvremove /dev/datavg/datalv_snap
```

删快照不影响源卷任何数据，只回收 COW 空间。快照是消耗品，备份完就删，别攒着。

## 常见错误自查

- lvs 里快照的 Data% 接近 100% → COW 空间快耗尽，立即删除快照或扩大（lvextend 快照卷）。
- 快照挂载后报错 → 快照已失效（COW 满），只能删除重建。
- merge 一直没生效 → 需要 umount 源卷并重新激活：lvchange -an 再 lvchange -ay，或重启。
- 拍快照时机不对 → 数据库应先 FLUSH TABLES WITH READ LOCK 或用应用层一致性命令，再拍快照。

## 小结

快照基于写时复制，瞬间创建、按需存旧块。用法口诀：拍、用、删——拍快照保时机，从快照挂载点做备份，做完立刻 lvremove。COW 空间盯 Data% 别打满。要整体回滚用 lvconvert --merge，但那是丢弃之后的写入，慎用。快照加上前两篇的动态扩容，LVM 的核心价值就齐了。
