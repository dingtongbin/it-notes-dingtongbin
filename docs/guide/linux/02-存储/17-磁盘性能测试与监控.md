# 磁盘性能测试与监控

磁盘是慢还是坏了？新存储能扛多少 IOPS？加盘值不值？回答这些问题要靠两样东西：fio 压测拿数据，iostat 观测看现状。这一篇讲怎么测、怎么读数。

## 先懂三个核心指标

| 指标 | 含义 | 机械盘参考 | SSD 参考 |
| --- | --- | --- | --- |
| IOPS | 每秒 IO 次数 | 100-200 | 数万到数十万 |
| 吞吐（MB/s） | 每秒数据量 | 100-200 | 数千 |
| 延迟（ms） | 单次 IO 耗时 | 5-15 | 0.1 以下 |

随机小 IO 吃 IOPS，顺序大块读写吃吞吐，两者不可兼得，测试时要分场景。

## fio：行业标准压测工具

```bash
sudo apt install fio
```

四个典型场景：

随机读（数据库类负载）：

```bash
sudo fio --name=randread --filename=/mnt/data/fio.test --size=2G \
  --rw=randread --bs=4k --iodepth=32 --direct=1 --runtime=60 --group_reporting
```

随机写：

```bash
sudo fio --name=randwrite --filename=/mnt/data/fio.test --size=2G \
  --rw=randwrite --bs=4k --iodepth=32 --direct=1 --runtime=60 --group_reporting
```

顺序读写（大文件拷贝类负载）：

```bash
sudo fio --name=seqrw --filename=/mnt/data/fio.test --size=2G \
  --rw=read --bs=1M --direct=1 --runtime=60 --group_reporting
```

参数解读：

- bs：块大小，4k 测随机、1M 测顺序。
- iodepth：队列深度，模拟并发压力。
- direct=1：绕过页缓存直写磁盘，必加，否则测的是内存。
- runtime：压测时长，写测试别跑太久伤 SSD。

输出里看三行：read IOPS、read BW（吞吐）、lat（延迟分布）。

## iostat：看实时状态

```bash
sudo apt install sysstat
iostat -dx 2
```

每 2 秒刷新各盘扩展统计，关键列：

- r/s、w/s：每秒读写次数。
- rkB/s、wkB/s：每秒读写数据量。
- await：平均 IO 等待毫秒数，机械盘超过 15、SSD 超过 2 就要警惕。
- %util：设备忙的百分比，长期接近 100% 就是瓶颈。

## 快速定位"谁在吃盘"

系统突然卡，先看是不是磁盘被打满：

```bash
iostat -dx 2          # 哪块盘忙
sudo iotop -o         # 哪个进程在读写（只显示有 IO 的）
pidstat -d 2          # 按进程统计 IO，适合脚本化
```

顺藤摸瓜：盘忙 → 进程 → 日志文件失控还是任务扎堆，对症处理。

## 页缓存的干扰

Linux 会把空闲内存拿来做磁盘缓存（free 里的 buff/cache），读文件很快是在吃缓存。评估真实磁盘能力时：测试加 direct=1；观察时可对比两次连续读的耗时差。

另外注意脏页回写节奏：大量写入后系统后台 flush 造成的周期性卡顿，可用 vm.dirty_ratio 等参数调优，属于进阶话题。

## 常见错误自查

- fio 测出几百 MB/s 的"随机 4k" → 忘了 direct=1，测的是缓存。
- iostat 的 %util 100% 但系统不卡 → SSD 并行能力强，%util 对 NVMe 参考意义有限，看延迟与队列。
- 测出性能远低于标称 → 检查是否经过 RAID5 校验、网络存储带宽、虚拟化超分。
- iotop 没输出 → 需要 root，且加 -o 过滤空转进程。
- 压测把生产盘写满了 → filename 指定测试文件并控制 size，测完删除。

## 小结

压测用 fio：分随机 4k 与顺序 1M 两场景，direct=1 绕缓存，看 IOPS、吞吐、延迟三项。观测用 iostat -dx 盯 await 与 %util，iotop 抓进程。记住"随机看 IOPS、顺序看吞吐、卡顿先看延迟"，磁盘性能的门道就通了。最后一篇讲备份与 rsync。
