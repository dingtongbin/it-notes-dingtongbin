# LVM 与 RAID 选型对比

LVM 和 RAID 都能把多块盘变成一个逻辑盘，初学者常混淆"该用哪个"。这一篇把两者放在一张表里对比，给出生产上的经典组合方案。

## 解决的问题不同

- RAID 解决的是可靠性与性能：镜像、校验、条带化，坏盘不丢数据。
- LVM 解决的是灵活性：空间池化、动态扩缩容、快照。

一句话区分：RAID 管"坏了怎么办"，LVM 管"不够了怎么办"。

## 核心对比

| 维度 | LVM | RAID |
| --- | --- | --- |
| 核心价值 | 空间抽象与弹性 | 冗余与性能 |
| 坏一块数据盘 | 数据丢失 | RAID 1/5/10 可降级运行不丢 |
| 在线扩容 | 原生支持，秒级 | 基本不支持，通常要重建 |
| 快照 | 支持 | 不支持 |
| 跨盘聚合 | 是 | 是 |
| 性能提升 | 无 | RAID 0/10 有明显提升 |
| 软件实现 | lvm2 | mdadm |

注意 LVM 本身没有冗余能力：VG 里某块 PV 坏了，落在它上面的 PE 数据就没了。这正是不能"只用 LVM 不用 RAID"的原因。

## 生产经典组合：RAID 打底 + LVM 上层

最稳妥的架构是两者叠加：先用 mdadm 做好 RAID 阵列保证冗余，再把阵列整个交给 LVM 池化管理：

```bash
sudo mdadm --create /dev/md0 --level=10 --raid-devices=4 /dev/sd[b-e]
sudo pvcreate /dev/md0
sudo vgcreate datavg /dev/md0
sudo lvcreate -L 500G -n datalv datavg
```

分层各司其职：底层 RAID 负责坏盘兜底，上层 LVM 负责灵活切分与扩容。之后要加容量，新盘做成新阵列再 vgextend 即可。

## 按场景选方案

| 场景 | 推荐方案 |
| --- | --- |
| 单块系统盘的笔记本/小 VPS | LVM 就够，坏了就重装 |
| 物理服务器系统盘 | RAID 1 双盘 |
| 数据盘，预算有限、读写均衡 | RAID 5 + LVM |
| 数据库等重写入关键业务 | RAID 10 + LVM |
| 临时加速缓存盘 | RAID 0 或 LVM 条带 |
| 家用 NAS 玩法 | mdadm RAID 5/6 |

云服务器（阿里云、AWS 等）一般用云盘的多副本机制替代 RAID，系统内只上 LVM 即可，自己再做软件 RAID 反而浪费且无意义。

## 决策清单

选型时按顺序自问：

1. 数据丢了能不能接受？不能 → 必须有冗余（RAID 1/5/10 或云盘多副本）。
2. 空间会不会不够？会 → 需要 LVM。
3. 写入压力大不大？大 → 选 RAID 10 而非 RAID 5。
4. 是云上还是物理机？云上跳过 RAID，物理机认真做。

## 常见误区

- 只做 LVM 以为有冗余 → LVM 不提供任何容错，PV 坏即数据坏。
- RAID 当备份用 → RAID 挡硬件故障，挡不住误删除和病毒，备份是另一套体系（见 rsync 一篇）。
- RAID 5 上跑重写入业务 → 校验计算拖慢写入且重建窗口风险大，换 RAID 10。
- 为省事跳过 mdadm.conf 持久化 → 重启阵列名漂移，挂载全乱。

## 小结

RAID 管冗余、LVM 管弹性，两者不冲突而是分层协作：底层 RAID 保数据不丢，上层 LVM 保空间好调。云环境用云盘副本替代 RAID，系统内只上 LVM。记住"RAID 不是备份"，该有的 rsync 备份一份都不能少。
